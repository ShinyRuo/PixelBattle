## 二、选型决策与理由

### 脚本语言：GDScript（不是 C#）

有 C++ 背景的人会本能地想选 C#，但对「AI 协作 + 2D + 单人开发」这个组合，GDScript 明显更优：

- **没有编译步骤。** 改一行存盘就生效。这直接决定了 AI 迭代循环的长度——
  自检全跑一遍 10 秒内完成，可以每改一小步就验证一次，而不是攒一堆改动赌一次编译。
- **语料充足、报错直白。** 引擎的一切文档、示例、社区代码都是 GDScript。
- **不锁死。** 以后想上 C#，装 .NET 版引擎、`Project > Tools > C# > Create C# Solution`
  即可，项目文件本身通用。GDScript 和 C# 可以在同一项目里共存。

C# 的代价是每次改动要 `dotnet build`，编辑器程序集热重载还有历史遗留问题。

### 渲染后端：gl_compatibility（不是默认的 forward_plus）

纯 2D 项目用 GL Compatibility：启动快、显存占用低、兼容性最好（含老显卡和 Web 导出）。
以后要 2D 全局光照或复杂后处理，改 `project.godot` 里 `renderer/rendering_method`
为 `forward_plus` 即可，一行的事。

### 分辨率：640×360 内部 / 1280×720 窗口 / stretch = viewport

`viewport` 拉伸模式 = 整个游戏按 640×360 逻辑分辨率渲染再整体放大，像素不会被插值糊掉。
配合 `default_texture_filter=0`（Nearest），这是像素美术的标准配置。

### MCP 选型：`@satelliteoflove/godot-mcp`

生态里有近十个 Godot MCP，主要差别在工具数量——**而工具定义直接吃 AI 的上下文窗口**。

| 候选 | 取舍 |
|---|---|
| `@satelliteoflove/godot-mcp` | ✓ **选它。** MIT，21 工具 86 action，读写分离（`*_read` 可安全自动放行）。专注 CLI 做不到的事：注入输入、冻结/步进游戏时钟、读运行时状态、截图 |
| `@yanhuifair/godot-mcp` | 358 个工具，功能最全但上下文开销过大，且 AGPL |
| `godot-mcp-runtime` | 更轻，但能力覆盖不如上面 |
| `@coding-solo/godot-mcp` | 2026-02 后未更新 |

**关键认知**：CLI（`godot_console.exe --headless`）已经能覆盖九成需求——导入、跑测试、
运行时冒烟。MCP 的增量价值只在「运行中的游戏」：注入输入、观察实时状态、截图。
所以骨架先用零依赖的 CLI 闭环跑通，MCP 最后接。

## 三、安装步骤（可复现）

### 1. 引擎

winget 直接装会失败（见下方问题 1），走镜像手动装：

```powershell
# 下载
$zip = "F:\Godot_PJ\_engine\godot472.zip"
Invoke-WebRequest -UseBasicParsing -OutFile $zip `
  "https://ghfast.top/https://github.com/godotengine/godot/releases/download/4.7.2-stable/Godot_v4.7.2-stable_win64.exe.zip"

# 校验（官方 SHA256，可用 `winget show GodotEngine.GodotEngine` 核对）
(Get-FileHash $zip -Algorithm SHA256).Hash.ToLower()
# 应为 731980f9608d61333e5baf54a2ef17210acc7a538446c0cb9969f002aca1e953

# 解包并改成命令行友好的名字
Expand-Archive $zip -DestinationPath "F:\Godot_PJ\_engine\4.7.2" -Force
cd F:\Godot_PJ\_engine\4.7.2
Rename-Item "Godot_v4.7.2-stable_win64.exe"         "godot.exe"
Rename-Item "Godot_v4.7.2-stable_win64_console.exe" "godot_console.exe"
```

> 重命名有讲究：console 包装器靠**自己的文件名去掉 `_console` 后缀**来定位主程序，
> 所以两个必须成对改成 `godot.exe` / `godot_console.exe`，不能只改一个。

加进用户 PATH：

```powershell
$dst = "F:\Godot_PJ\_engine\4.7.2"
$old = [Environment]::GetEnvironmentVariable("Path","User")
[Environment]::SetEnvironmentVariable("Path", "$old;$dst", "User")
```

### 2. VSCode 插件

```powershell
code --install-extension geequlim.godot-tools   # LSP + 断点调试，v2.7.1
code --install-extension alfish.godot-files     # .tscn/.tres 高亮，v0.1.6
```

`godot-tools` 提供 `gdscript` / `gdscene` / `gdresource` / `gdshader` 四种语言，
文件扩展名已自动关联，不用手写 `files.associations`。

pip 会把 `gdlint.exe` / `gdformat.exe` 装进 Python 的 `Scripts` 目录，记得加 PATH：
`C:\Users\<用户名>\AppData\Local\Python\pythoncore-3.14-64\Scripts`

### 4. GUT 测试框架

AssetLib 在墙内不稳，走镜像下 zip。**下 tag 而不是 `main`** ——
`main` 会随时间漂移，同一条命令过几个月装出来的不是同一个版本。

```powershell
$V = "9.7.1"
Invoke-WebRequest -UseBasicParsing -OutFile "$env:TEMP\gut.zip" `
  "https://ghfast.top/https://github.com/bitwes/Gut/archive/refs/tags/v$V.zip"
Get-FileHash "$env:TEMP\gut.zip" -Algorithm SHA256    # 见下表核对
Expand-Archive "$env:TEMP\gut.zip" -DestinationPath "$env:TEMP\gut_ex" -Force
Copy-Item "$env:TEMP\gut_ex\Gut-$V\addons\gut" "F:\Godot_PJ\PixelBattle\addons\gut" -Recurse -Force
```

| 版本 | 装的时间 | zip 的 SHA256 |
|---|---|---|
| 9.6.1 | 建环境时 | 未记录（当时下的是 `main`，不可复现） |
| 9.7.1 | 2026-08-28 | `14969AA46ADC84AA08CDD21B9F6D1A64ADDD92AE60B36F02D0521ED305AA4086` |

> **这个哈希是自己算的，不是官方公布的校验值。** GitHub API 和 codeload
> 两条路走 `ghfast.top` 都返回 403，取不到官方 checksum，也没法用第二条
> 独立路由交叉验证。**它只能保证「以后重下的是同一个 zip」，不能证明
> 「这个 zip 就是上游发布的那个」。** 哪天代理能通 API 了应该补一次核对。
>
> 实际做的验证是行为层面的：装上之后 `check.ps1` 跑出
> **140 用例 / 3054 断言，与 9.6.1 逐个相同** —— 升级没有偷偷少测什么。
> 这正是 §自检契约里那条「测试静默消失」防线的用处。

#### 为什么从 9.6.1 升到 9.7.1

9.6.1 每次跑完都打一行
`This version of GUT may not be compatible with Godot 4.7.2.`
自检的失败模式检查靠 stdout 关键字匹配，长期挂着一行版本警告
会让人对告警脱敏。升级后该行消失。

版本差异很小：整个 addon 只多了一个 `gut_constants.gd`（257 → 259 个文件，含 `.uid`）。

### 5. Godot MCP

```powershell
npx -y "@satelliteoflove/godot-mcp" --install-addon "F:\Godot_PJ\PixelBattle"
```

然后在项目根建 [.mcp.json](../.mcp.json)（Claude Code 会自动读）：

MCP addon 有 74 个文件 / 352 KB，**选择提交进 git**——因为 `project.godot` 里启用了这个插件，

### 6. Git 仓库

```powershell
git init -b main
git config core.quotepath false     # ← 必做，见下
```

**`core.quotepath false` 是必须的。** 默认情况下 git 会把非 ASCII 路径转义成八进制
（`Docs/环境搭建记录.md` → `"Docs/\347\216\257\345\242\203..."`）。文档目录用了中文名，
不关掉的话任何解析 `git` 输出的脚本或工具都会拿到读不了的路径。

`.gitattributes` 已把 `.tscn` / `.tres` / `.gd` 显式标成文本——Godot 的场景和资源是文本格式，
这是相比 UE `.uasset` 最大的红利（可 diff、可 merge、AI 能直接改），别让 git 猜错类型。

## 四、踩到的 5 个坑

### 问题 1：winget 装 Godot 失败

```
InternetOpenUrl() failed. 0x80072efd
```

**根因**：本机 GitHub 直连不通，而 winget 的 Godot 包指向 GitHub Releases。
这不是网络抖动，重试永远不会成功。

**解法**：拼 `https://ghfast.top/` 前缀走代理（`https://gh-proxy.com/` 同样可用）。
npm registry 直连正常，PyPI 用清华源。`www.godotengine.cn` 也不通。

**代理下载的可执行文件必须核对 SHA256。** `winget show <包名>` 会打印官方哈希，
是现成的对照源——不用另外去找。

### 问题 2：命令行跑 `--headless` 一片空白

**根因**：Windows 上 `godot.exe` 是 GUI 子系统程序，stdout 不回传给调用它的终端。

**解法**：命令行一律用官方提供的 `godot_console.exe` 包装器。这条影响所有自动化——
CI、任务、AI 自检全都得走 console 版。

### 问题 3：`check.ps1` 满屏乱码 + 语法错误

```
Write-Host ("鈺? * 64) -ForegroundColor DarkGray
Missing closing '}' in statement block
```

**根因**：文件存成了**无 BOM 的 UTF-8**，而 PowerShell 5.1 会按系统 ANSI 代码页（GBK）
去解，中文和框线字符全部错位。

**解法**：`.ps1` 必须存成 **UTF-8 with BOM**：

```powershell
$t = [IO.File]::ReadAllText($f, [Text.UTF8Encoding]::new($false))
[IO.File]::WriteAllText($f, $t, [Text.UTF8Encoding]::new($true))
```

`.gitattributes` 里也把 `*.ps1` 标成 `eol=crlf`。

### 问题 4：`.gdlintrc` 解析失败

```
yaml.parser.ParserError: expected <block end>, but found '['
```

**根因**：配置值是正则，而 YAML 里**以 `[` 开头的裸字符串会被当成数组**。

**解法**：别凭记忆手写配置格式，用工具导出默认值再改：

```powershell
gdlint -d      # 导出到当前目录的 gdlintrc（注意：不带点）
```

需要加引号的行（如 `signal-name: '[a-z]...'`）导出来就是带引号的，照抄即可。
gdlint 读取时 `.gdlintrc` 和 `gdlintrc` 都认，项目里保留带点的那个。

### 问题 5：写进 `project.godot` 的注释消失了

**根因**：引擎会重写这个文件，跑一次 `--import` 就会发生。它做三件事：

1. **删掉所有注释**
2. **省略等于默认值的项**（如 `window/stretch/aspect="keep"` 写了也会消失——这是归一化，
   不是丢失，看不到不代表没生效）
3. **自动补插件需要的段**（启用 Godot MCP 后自动加了 `[autoload] MCPGameBridge`
   和 `[godot_mcp]` 段，别手动删）

**解法**：配置说明只能写在 CLAUDE.md / 本文档里，不要写在 `project.godot` 内。

## 五、另外三个设计取舍

### 自检脚本默认静默

第一版 `check.ps1` 把每个阶段的输出全打出来，一次自检刷 200 多行导入进度条。
对人是烦，**对 AI 是致命的**——每次自检白白吃掉几千 token 上下文。

改成：**成功时只报一行 `✓`，失败时才打完整输出**（并滤掉进度条行），
`-Full` 参数保留全量输出的能力。输出从 200 行压到 40 行。

同理，用 `Start-Process` + 重定向到临时文件来捕获外部程序输出，而不是 `2>&1`——
PowerShell 5.1 会把原生程序的 stderr 包成 ErrorRecord，即使程序返回 0 也把 `$?` 弄成 false，
判断结果就不可靠了。

### 工具查找要兜底

`gdlint` 刚 `pip install` 完，当前终端的 PATH 还是旧的；VSCode 任务继承的也可能是启动时的旧环境。
第一次跑自检时 gdlint 被静默跳过了。

`check.ps1` 里加了 `Resolve-Tool`：先查 PATH，查不到就去 Python 的 `Scripts` 目录捞。
**依赖环境变量刷新是不可靠的**，脚本得自己找得到工具。

### 测试分快慢两档（M2 期间加的）

自检从 5 秒长到了 **105 秒**，其中 98 秒在 GUT，而 GUT 的 98 秒里 **83 秒在一个文件里** ——
配平扫描要跑完整的局，`rational` 流派一局 2.1 秒（每花一笔钱就重估一遍全部候选项），
写死优先级的 `balanced` 只要 93 毫秒。

**这是个工具链问题而不是性能问题**：改一行代码等一分半钟，人就会开始不跑自检，
而不跑自检比测试慢危险得多。做了两件事：

1. **记忆化**。「默认配置 + rational」这一组在六条测试里被要了 21 次，
   而不同的种子只有 5 个。模拟是确定性的，所以缓存是**纯粹省时间，不损失任何严谨性**。
   全量从 98 秒降到 58 秒。
2. **分档**。靠整局扫描才能验的配平结论集中到 `tests/test_balance_scan.gd`，
   默认跳过，`-Deep` 才跑。快档 13 秒。

分档的实现方式值得记一笔：**走 GUT 的 `should_skip_script()`，而不是「不扫描那个目录」。**
GUT 会先实例化脚本再判跳过，所以慢档文件的解析错误在快档照样暴露，
报告里也会打出 `[Script skipped]` 并计入 risky。挪目录看起来更简单，
但那样一来那个文件哪天解析不过都没人知道 —— 正是 CLAUDE.md 里
「测试静默消失」那条防线要防的东西，而分档本身恰好是最容易制造这种洞的改法。

验证方式是行为层面的：分档后跑 `-Deep` 得到 **140 用例 / 3054 断言，与分档前逐个相同**。
