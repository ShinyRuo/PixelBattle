### 已确认需求

- 忍者有专属施法动作，每段 6 帧，不随攻击速度变化，在第 4 帧释放技能。

- 每个 buff 有专属环身光效，跟随受益忍者；召唤物配置独立的待机 / 移动 / 攻击 / 死亡四态，远程召唤物另配子弹。

### 施法时序方案

动作帧指素材的六张关键帧，不是六个显示器刷新帧。模拟层记录开始 / 释放 / 结束 tick，画面根据同一时间轴取帧；伤害不能依赖 `AnimatedSprite2D` 的回调，否则低帧率、无画面模拟与倍速会改变结果。

建议默认总时长 0.6 秒、每帧 0.1 秒，**进入第 4 帧**即开始后的 0.3 秒释放；在 20 tick/s 下为第 6 tick，收招结束为第 12 tick。此时长已向用户询问，尚未确认，不写入运行配置。游戏倍速 / 暂停应同步影响动作和模拟，攻击速度不影响施法。

释放的含义：子弹在该时刻生成；连线在该时刻建立；即时增益 / 伤害在该时刻生效；延迟爆炸或多段技能从该时刻开始自己的计时。原有飞行时长、延迟与段间隔须逐技能归类，避免重复增加前摇或把延迟命中改成立即命中。第 5–6 帧为收招，不能因已经释放就立刻跳回普攻动画。

推荐仅主动施法占用这段动作；普攻触发被动、常驻光环、阵亡触发各走对应事件表现。控制是否打断、释放前取消是否返蓝、收招是否允许移动 / 普攻、引导如何衔接循环动作，需要在统一时序实现时明确并测试，不能悄悄改掉现有机制。

### 表现配置与素材边界

核心仅保存稳定 ID、效果状态与确定性事件，纹理 / 场景 / 动画资源由表现层加载。沿用现有形象和子弹资源入口，新增的表现配置需要有读取与校验后才对外宣称支持。

- 施法：按忍者 + 技能映射六帧动作、发射点和朝向；通用动作回退仅保障能运行，不算专属素材完成。
- 技能：拆成起手、释放、飞行 / 连线、命中、持续、结束，允许同一技能组合多种效果。范围表现必须读真实范围，特效大小不反推伤害范围。
- buff：获得短闪、前景 / 背景环身循环、消失 / 破盾反馈；跟随脚底或躯干锚点、角色尺寸和翻转。光环覆盖圈与受益者身上的 buff 光效分开。
- 召唤物：独立形象键、四态动画、脚底 / 发射 / 受击锚点、远程子弹键；影分身可显式继承忍者形象，忍犬与其他独立召唤物不能默认借用召唤者皮肤。寿命结束与死亡的退场方式单独配置。

## 1. 三层，以及每层的边界

| 层               | 回答什么                                       | 类                                                             | 谁读它          |
| ---------------- | ---------------------------------------------- | -------------------------------------------------------------- | --------------- |
| **效果层** | 「他身上现在有什么，因此他的攻/防/速是多少」   | `PBBuff` / `PBBuffState` / `PBBuffBag` / `PBBuffRules` | sim 的每个读点  |
| **技能层** | 「这一发怎么放、落在谁身上、挂哪几个效果」     | `PBSkill` / `PBSkillCast` / `PBSkillRules`               | `PBBattleSim` |
| **操作层** | 「玩家点了哪一格、接下来那一下点击是什么意思」 | 泛化现有`PBFieldPicker` / `PBCommandCard`                  | 渲染层          |

**分层的判据不是「大招 vs 技能」，是「定义 / 这一波的状态 / 玩家的意图」。**

今天 `PBUltimate` 把前两样混在一个类里 —— 那正是它需要一个
「只带设定不带状态」的 `clone()` 外加一个 `reset()` 的全部原因。
拆开之后这两样税自动消失。

## 2. 效果层（buff）

### 2.1 三个类，对着 GAS 的三个概念

| 本案            | GAS                                     | 是什么                                      | 存哪                         |
| --------------- | --------------------------------------- | ------------------------------------------- | ---------------------------- |
| `PBBuff`      | `GameplayEffect`                      | **定义**，不可变，全局一份            | `data/buffs/*.tres`        |
| `PBBuffState` | `ActiveGameplayEffect`                | **一份正在生效的**：到期 tick、谁给的 | 单位身上                     |
| `PBBuffBag`   | `AbilitySystemComponent` 里聚合那一半 | 一个单位身上的全部 + 合计值                 | `PBAttacker` / `PBEnemy` |

**`PBBuffBag` 不认识 `PBAttacker`，也不认识 `PBEnemy`** —— 它收裸值、返回裸值。
和 [PBActorPose] 同一条规矩：敌我两边字段名不同，收裸值才能一份实现两处用。
两套的话「减速的判定」迟早在两边分叉，而那不报错。

### 2.2 三档时长

| 档           | 进不进 bag     | 语义                                | 例                            |
| ------------ | -------------- | ----------------------------------- | ----------------------------- |
| `INSTANT`  | **不进** | 当场改一次量，然后就没了            | 回血、回蓝、直接伤害          |
| `DURATION` | 进             | 在窗口内改「率」                    | 5 秒 +30% 攻、3 秒 −50% 移速 |
| `PERIODIC` | 进             | 窗口内每 N tick 触发一次`INSTANT` | 持续回血、中毒                |

> **持续回血是「周期性的瞬间回血」，不是一个修饰符。**
> 分不清这一条的话，回血会被写成「血上限 +X」那一类，
> 而它一过期血就掉回去 —— 那不是治疗，那是护盾，而且是一个坏护盾。

### 2.3 核心不变量：持续效果永远不写回基础字段

```
瞬间效果改的是「量」（hp / mp）      —— 写进字段
持续效果改的是「率」（倍率 / 加值）  —— 永远不写字段，只在用的那一刻问一次
```

反过来（上 buff 时 `dps *= 1.3`，过期时 `dps /= 1.3`）看起来更省，但：

- 浮点乘除不可逆，几十次上下之后基础值会漂
- 两个 buff 重叠时**先后顺序开始有意义**，而那说不清
- 期间基础值本身变了（装备重算、羁绊重建）就永久错位
- **三条全都不报错**，只表现为「这个人打着打着好像变弱了」

所以是 `damage_per_shot() * bag.scale(DAMAGE)`，在开火那一行乘，不在别处。
这个项目为「同一件事两把尺子」付过四次代价，这一条是同一个形状。

### 2.4 词汇表

和 [PBBondFunctionRules] 的 `ALL` 同一套：一份 const 键表，加载时校验，
**拼错的键当场报错**。静默什么都不发生的话，从现象反推不出来。

**己方（挂在 `PBAttacker` 上）**

| 键                     | 落在哪个读点                             | 多份怎么合     | v1 |
| ---------------------- | ---------------------------------------- | -------------- | -- |
| `heal`               | `hp`，上限封顶                         | 累加           | ✅ |
| `mana`               | `mp`，上限封顶                         | 累加           | ✅ |
| `shield`             | `take_damage` 先扣盾                   | 累加           | ✅ |
| `damage_scale`       | `damage_per_shot()`                    | **连乘** | ✅ |
| `defence_add`        | `PBStatRules.strike_damage` 的 defence | 累加           | ✅ |
| `attack_speed_scale` | `attack_interval()`                    | 连乘           | v2 |
| `move_speed_scale`   | `PBMoveRules`                          | 连乘           | v2 |
| `reach_scale`        | `can_reach` / `stop_gap`             | 连乘           | v2 |
| `mp_regen_scale`     | `regen_mana`                           | 连乘           | v2 |
| `cooldown_scale`     | `PBSkillCast`                          | 连乘           | v2 |

**敌方（挂在 `PBEnemy` 上）**

敌人已有护甲、忍术抗性、近远程攻击与效果袋；没有己方的蓝量 / 技能槽结构。
以下保留 M7 的基础词汇，并补入后续已接通的防御与概率效果；完整键表以 `PBBuffRules` 为准。

| 键                     | 落在哪个读点                                      | 多份怎么合 | v1 |
| ---------------------- | ------------------------------------------------- | ---------- | -- |
| `hurt`               | `take_damage` 内部乘一次（易伤）                | 连乘       | ✅ |
| `damage_taken`       | `take_damage` 内与易伤相乘，0 为无敌             | 连乘       | ✅ |
| `shield`             | `take_damage` 倍率折算后调用 `buffs.absorb`      | 累加余量   | ✅ |
| `dodge`              | `take_damage` 仅对普攻掷闪避                    | 累加概率   | ✅ |
| `crit_chance`        | `PBCritRules.enemy_strike` 出手时掷一次         | 累加概率   | ✅ |
| `crit_damage`        | `PBCritRules.enemy_strike` 的额外暴伤           | 累加       | ✅ |
| `enemy_speed_scale`  | `advance` / `march_to` 内部（个体减速、定身） | 连乘       | ✅ |
| `harm`               | `take_damage`（瞬间/周期伤害，中毒灼烧）        | 累加       | ✅ |
| `enemy_damage_scale` | `_enemies_attack` 出手那一行（削弱）            | 连乘       | v2 |

> **`hurt`、`damage_taken` 与护盾必须在 `PBEnemy.take_damage` 里面结算，不在调用方。**
> 调用方有五处（单体、AOE、连续输出、子弹命中、大招落地），
> 而漏乘一处的表现是「某一种攻击方式吃不到易伤」——
> 要盯着日志看很久才发现。放进类里就只有一个读点。
> 护盾按效果袋槽位顺序消耗，各自到期、同 id 刷新；闪避或无敌时不消耗。
> 连续输出的 `damage_to_kill` 必须同步计入倍率与有效护盾，无敌时返回 `INF`，避免溢出伤害凭空增加。
>
> 同理 `enemy_speed_scale` 放在 `advance` / `march_to` 里面，
> 不在 `_advance_and_leak` 的三个调用点上各乘一遍。

**v1 己方砍到五个、敌方砍到三个是有意的**：每个键就是一个读点，
而一个读点漏乘的表现是「这个 buff 好像没用」，不报错。
这八个够覆盖医疗忍术 + 增伤 + 护盾 + 易伤 + 单体控。

> **`PBBuffRules.ALL` 里的键 = 已经接上读点的键**（M7-a 写代码时定的，
> 比上面那句更紧）。**一个拼错的键有报错拦着，一个拼对了却没人读的键
> 什么都不会说** —— 数据、界面、日志全都正常，只有伤害数字不对，
> 那比拼错难查得多。
>
> 所以键是**跟着读点一起进来的**，不是先把词汇表铺满：
> M7-a 只有三个（`damage_scale` / `heal` / `mana`），
> 护盾、易伤、个体减速那几个在 M7-c / M7-d 连同它们的读点一起加。
> 上面两张表因此是**路线图，不是当前的 `ALL`**。

> `attack_speed_scale` 单独说一句（v2 才做，但形状现在就定）：
> 间隔是 `prime()` 缓存的，所以 buff 要在 `attack_interval()` 的**返回值**上乘，
> 不是回去改缓存。副作用是「buff 在两发之间过期」不追溯上一发 ——
> 那是对的，出手节奏在开火那一刻就定了。

#### 数值怎么长：按施法者的**等级**，而且配表（决策 7）

定值不行：一个回 120 血的技能在第 5 波很强、第 30 波等于没有，
**而它不报错**，只表现为「这个角色后期没用」。

**表的形状和 `PBCharacter` 的二级属性一模一样**，不是新发明的：

```gdscript
# PBCharacter 已经是这个写法
strength: float          # 1 级时多少
strength_growth: float   # 每升一级涨多少
# PBStatRules.of()：strength + strength_growth * (level - 1)
```

```
# data/buffs/<id>.tres
mods        = { &"heal": 80.0 }    # 1 级时
mods_growth = { &"heal": 14.0 }    # 每级加多少
```

**实际值 = `mods[键] + mods_growth[键] × (施法者等级 − 1)`**，
一处算（`PBBuffRules.resolve`），别处不重算。

**校验一条**：`mods_growth` 里出现的键必须也在 `mods` 里（反过来不要求）——
只写成长不写基数是纯粹的笔误，而它静默生效成「1 级时是 0」。
率型键（`*_scale`）**允许**配成长，只是通常留空：它无量纲，不需要跟难度曲线走。

##### 为什么是等级而不是战力

不是「战力的一个便宜近似」——**它对的是另一条曲线。**

```
伤害  ↔ 敌人血量 ↔ 战力曲线      ← 技能的直接伤害走 skill.power_mult × 战力
治疗  ↔ 己方血量 ↔ 等级曲线      ← buff 的数值走这一条
```

己方血量 `hp = hp_base + strength × hp_per_strength`，而 `strength` 就是
按等级线性长的（`PBStatRules.of`）。**所以按等级缩放的治疗，
大致守住「回多少比例的血」这个不变量**，而按战力缩放的会跟着稀有度、
星级、装备一起飘 —— 那几样抬的是输出，不是血。

顺带它让指令卡上那个「升级」按钮对治疗角色第一次有意义：
在此之前升级只抬二级属性，而治疗角色的产出跟二级属性没关系。

##### 等级在**建攻击者时**就算完，sim 看不到它

`PBAttacker` 身上没有 `level` 这个字段，也不该有 ——
它顶上写着「属性克制、科技、羁绊、装备**全部已经乘进来了**，
战斗层不认识那些系统，它只认这个数」。buff 走同一条：

```
PBSkillCast.mods: Dictionary   # 键 → 这一波的实际数值，等级已经算进去
```

两条后果说清楚：**一波之内改等级不生效**（今天也改不了，升级只在准备阶段），
以及**尾兽不走这条路** —— 它的强度按 `beast_level` 由 `PBBeastRules` 算，
自己有一套，别接进来变成第二把尺子。

> 没有等级的施法者（敌人、尾兽）默认按 1 级算，成长项贡献 0，
> 取到的就是基数 —— 不需要为它们分一条支路。

> **一个以后可能要的键，现在不做**：`heal_pct`（按目标最大血的百分比回）。
> 那是比等级更硬的不变量，但它把治疗和「目标是谁」绑在一起，
> 定价上要另算一遍。等真有需要时它就是词汇表里多一个键，不动结构。

### 2.5 叠加：默认刷新，显式独立周期层例外

| 策略            | 语义                                                         | 做不做 |
| --------------- | ------------------------------------------------------------ | ------ |
| `REPLACE`     | 同一个 buff id 只留一份，重复施放**整份覆盖**（数值和到期都用新的） | ✅     |
| `STACK`       | 叠层，`max_stacks` 封顶                                    | ❌     |
| `INDEPENDENT` | 每次各一份，各自计时；仅敌方周期伤害及其减甲，`stacks=1` | ✅（2026-09-16） |

按原版傀儡之体的独立计时器补入：每次普攻挂一层，每秒一跳、五跳后清除该层及其减甲。伤害 / 穿透 / 增伤及羁绊减甲使用施加快照；减攻速另配普通刷新效果，不随层数连乘。其他种类的独立叠层由加载校验拒绝。

和项目已记录的立场一致 —— `PBBattleSim._slow_scale` 那里写着：
「等真会重叠时，怎么叠是一个要有依据的设计决定，不该现在拍一个」。

> **「整份覆盖」不是「到期取较长者」**（M7-a 写代码时改的）。
> 取较长会让「先挂一个长的弱档、再挂一个短的强档」得到
> **强档持续很久** —— 比两者都好，而没有人要过那个东西。
> 整份覆盖同时也和 `_buff_scale` / `_buff_until` 原来那两行逐字一致
> （那里写的就是「后来者覆盖前者」），**M7-a 的迁移能逐位相同靠的正是这一条**。

键是 **buff id 单独**，不是 `(buff id, 施法者)`。代价说清楚：
两个医疗忍者给同一个人上同一个持续回血会互相覆盖。角色数少，先这样；
要改就是把键换成二元组，`PBBuffBag` 内部的事，外面一行不动。

### 2.6 容量：满了顶掉剩余时间最短的那个

bag 的**普通槽位固定为 6**，随对象池一起预分配。独立周期层放在额外的可复用槽中，普通溢出不覆盖它们，它们也不挤占普通槽。

独立层不设人为上限；并发层数超过历史容量时才创建新状态，过期 / 清空后复用，战斗结束随对象池释放。这是为保留原版无限叠层增加的按需扩容，不是每次命中都创建对象。大量叠层时查询成本随层数增加，性能压力留待数值回归时测量。

满了之后**顶掉剩余时间最短的那一个**，不是丢掉新来的那个。
丢新的话表现是「我上的 debuff 没生效」，而它不报错；
顶掉最短的至少保证「刚放的技能一定看得见效果」。

### 2.7 过期：查询是真相，清扫只是回收

```
bag.scale(key) 遍历时按 tick 过滤   ← 真相
每 tick 末尾扫一遍删掉死条目        ← 只是回收槽位和 UI 行
```

**漏跑一次清扫不可能改变任何结算结果。** 反过来（删除即真相）的话，
清扫的时机、顺序、和暂停的关系全都变成正确性问题。
现有的 `_speed_scale()` / `_damage_scale()` 就是这个写法，照抄。

### 2.8 tick 顺序，以及敌人那一侧的两条坑

`step()` 现在是八步，插两处：

```
_tick += 1
_resolve_skills()      ← 原 _resolve_ultimates；技能落地 = buff 挂上
_tick_buffs()          ← PERIODIC 那一档在这里触发（回血、中毒）
_move_attackers()
_aim_targets()
_advance_shots()
_deal_damage()         ← 读 bag.scale(damage_scale)
_enemies_attack()      ← 读 bag.scale(defence_add) 和护盾
_advance_and_leak()    ← 读 bag.scale(enemy_speed_scale)
_separate()
_sweep_buffs()         ← 纯回收
```

**这一 tick 挂上的 buff 对这一 tick 的出手生效** —— 和现有全场增伤
（`_buff_until = _tick + ticks`，读的时候 `_tick <= _buff_until`）一致。

#### 坑一：敌人是对象池复用的，`spawn()` 必须清 bag

不清的话上一波的减速会漏进这一波，表现是「后半局的怪好像变慢了」。
**这和代码里已经记着的「大招冷却漏进下一场」是同一个形状**
（`PBUltimate.reset()` 顶上那段），而它同样不报错。

#### 坑二：全场减速和个体减速是两个东西，都要留着

`PBEnemy.advance` 顶上写着：

> 它是个参数而不是敌人身上的一个字段，因为减速是**场的属性**不是单位的属性
> —— 存到每个敌人身上的话，新出场的敌人会漏掉当前正生效的减速。

那条理由今天仍然成立，所以**全场那一份不动**。个体减速是新加的一层，
两者**相乘**：

```
实际速度 = speed × 全场 speed_scale × 个体 bag.scale(enemy_speed_scale)
```

一条测试钉着这个乘法：全场定身（0.0）期间再上一个个体减速，速度仍是 0。

### 2.9 现成的第一个客户

M3-d 那个全场增伤 `_buff_scale` / `_buff_until` **改成走 bag**（挂在每个攻击者身上）。

这不是顺手重构，是**唯一一条能验证 bag 是对的路**：它有一批既有测试钉着，
改完必须逐位还绿。全场减速 `_slow_scale` 不动，理由见上。

## 3. 技能层

### 3.1 定义与状态拆开

```gdscript
# PBSkill —— Resource，data/skills/*.tres，不可变
id, name_key, icon_key
anim_key                                  # 对上已有的 PBActorSkin.skill_anims
target: Target                            # 玩家要点什么
affects: Party                            # 结算落在哪一边（不能叫 Side，见下）
cooldown_seconds, delay_seconds, mp_cost
radius, max_targets
power_mult, element_override              # 伤害 = 施法者战力 × power_mult
on_hit:  Array[StringName]                # 命中目标挂哪几个 buff
on_self: Array[StringName]                # 施法者自己挂哪几个
# 外加现有那五个全场字段（gather / knockback / slow / team_damage / reset_cd）
```

```gdscript
# PBSkillCast —— RefCounted，一波一份，战斗结束就扔
skill: PBSkill
ready_at: int
spot: Vector2        # GROUND 档的待落地落点
target_slot: int     # ALLY / ENEMY 档锁定的那一个
lands_at: int        # -1 = 手上没有待落地的技能。**这才是「有没有一发在路上」的哨兵**
caster_level: int    # 只用来算效果数值（决策 7）
```

> **哨兵是 `lands_at`，不是 `spot`**（M7-c 落地时改的）。M7-b 之前只有
> `GROUND` 一种技能，「有落点」和「有一发在路上」永远同时成立，所以拿
> `NO_SPOT` 当哨兵是够用的。`NONE` 档进来之后那条等价关系断了 ——
> 它既没有落点也没有锁定谁，**但照样有一发在路上**。
> 换成 `lands_at` 对 `GROUND` 档是逐位等价的：两者在 `cast` / `land` /
> `reset` 里从来都是一起设、一起清。

> **`caster_level` 记的是等级，不是算完的数值**（M7-c）。[PBSkill] 建好之后
> 还会被改（`PBBondFunctionRules.apply_to_skill` 就是这么干的），
> 预先把效果数值算好存一份的话，后改的那一下不会跟着更新 ——
> 表现是「这个羁绊功能好像没生效」，不报错。存等级、用的时候现算，
> 就没有第二份真相。

### 3.2 目标与影响是**两根轴**，不是一个枚举

| `target`（点什么） | `affects`（落在谁） | 组合出来是什么                |
| -------------------- | --------------------- | ----------------------------- |
| `NONE`             | ALLIES                | 自增益 / 全队增益，点一下就放 |
| `NONE`             | ENEMIES               | 全场打击                      |
| `ALLY`             | ALLIES                | **医疗忍术**            |
| `ENEMY`            | ENEMIES               | 单体爆发、单体控              |
| `GROUND`           | ENEMIES               | **现在的大招**          |
| `GROUND`           | ALLIES                | 团队治疗圈                    |

合成一个枚举的话「地面范围治疗」表达不出来，而那是治疗系角色第二个技能的
自然形态 —— 也就是决策 6 里那两格中的一格。

**没有 `SELF` 这一档**：自增益就是 `target = NONE` + `on_self`。
两种写法表达同一件事就是两把尺子。

数据断言：`target == ALLY ⇒ affects == ALLIES`，`target == ENEMY ⇒ affects == ENEMIES`。

### 3.3 施法延迟只对 `GROUND` 有意义（决策 3）

施法延迟存在的**全部理由**是 §02 的预判窗口（`PBUltimate` 顶上写着，
那两条分层验收全建在它上面）。而锁定单体的技能没有预判可言 ——
目标跟着走，落点也跟着走。

所以：**`target != GROUND` 时 `delay_seconds` 必须为 0**，写成数据测试的一条断言。
允许非 0 的话「飞行途中目标死了怎么办」「飞行途中目标跑出射程怎么办」
两个问题要现在回答，而它们没有依据。

玩家已经拍了不要飞行体，所以这一条同时是决策 3 的落点。
视觉上要不要画一道光弧是**渲染层的事，且它不参与判定** ——
那是 `PBProjectile` 顶上那条「渲染层画一道假弹道是便宜的，但它会撒谎」的另一面：
不撒谎的前提是它不声称自己有飞行时间。

### 3.4 大招归位：留在 `PBSimConfig`，不下沉到 `.tres`

大招 = **每个角色的 0 号技能**，仍由 `PBCombatRules._build_skill`
（M7-b 落地时从 `_build_ultimate` 改名）按 `PBSimConfig` 生成，
一个数不动。角色表里的 `skill_ids` 是**额外**的。

理由用项目自己记下来的那一条（`PBCharacter.reach` 的注释）：

> 具体距离是要扫的参数，写在 `PBSimConfig` 里才扫得动；
> 写进 30 个 `.tres` 等于把可调参数散进数据文件。

界线因此很清楚：**全 30 个角色共用的那一份走配置，逐角色独有的走 `data/skills/`。**

`PBBondFunctionRules.apply_to_skill`（M7-b 落地时从 `apply_to_ultimate` 改名）
与 `PBBeastRules` 照旧写 0 号技能，**结算逻辑一行不用改** ——
五个字段（`gather` / `radius` / `slow_scale` / `slow_ticks` / `team_damage_scale` /
`buff_ticks`）的写法原样保留，`PBSkill` 就是保留它们的那个类。
签名改了（参数类型从 `PBUltimate` 换成 `PBSkill`），那是重命名的代价，
不是逻辑的代价。

### 3.5 门槛只有一份

```gdscript
PBBattleSim.can_cast(attacker, skill_index) -> bool   # 活着 / 冷却好了 / 蓝够
PBBattleSim.cast_skill(attacker, skill_index, order) -> bool
```

指令卡那一格的亮/灰读 `can_cast`，点下去走 `cast_skill`，
而 `cast_skill` 第一行**再问一次** `can_cast`。
各写一份的话「按钮亮着但点了没反应」迟早出现 —— 现有的
`cast_ultimate` / `can_cast` 已经是这个写法，照抄。

**冷却和蓝两道门槛都保留**，理由沿用 `PBUltimate.mp_cost` 顶上那段：
冷却管「多久来一次」，蓝管「连着放几发」，只有冷却的话智力没有用途。

### 3.6 一个角色最多两个（决策 6），正好接上 §08 的稀有度阶梯

`PBCharacter.skill_ids: Array[StringName]`，**长度上限 2**，数据测试钉着。

把大招数进去之后，它和 §08 那张表严丝合缝：

| 稀有度 | §08 写的技能数 | 本案怎么兑现                         |
| ------ | --------------- | ------------------------------------ |
| R      | 1               | 大招                                 |
| SR     | 2               | 大招 + 1                             |
| SSR    | 3               | 大招 + 2                             |
| USR    | 3 + 专属机制    | 大招 + 2 + 羁绊功能档 / 尾兽那套词汇 |

**这不是巧合凑出来的** —— §08 那句「稀有度剩下的价值走技能数，不走数值」
本来就要一个技能表来承接，而它从 M2-a 起一直空着
（`PBCharacter` 顶上「已知的省略」第一条）。

### 3.7 结算放新文件

`battle_sim.gd` 现在 **938 / 1000 行**。技能结算（挑目标、圈人、挂 buff、
全场效果）进 **`src/core/rules/skill_rules.gd`**，和已有的两块对称：

| 类                         | 答什么                         |
| -------------------------- | ------------------------------ |
| `PBTargetRules`          | 敌人该打哪个己方单位           |
| `PBMoveRules`            | 己方单位该往哪儿走             |
| **`PBSkillRules`** | **这一发技能落在谁身上** |

`PBBattleSim` 只留「什么时候调它」和状态推进。

## 4. 操作与表现

### 4.1 状态机泛化

现在是 `PBFieldPicker.Aim { OFF, TARGET, ULTIMATE }`。改成：

```gdscript
enum Aim { OFF, TARGET, SKILL }
var aim_skill: int = -1     # SKILL 档时，是 0 号还是几号技能
```

**接下来那一下点击是什么意思，由那个技能自己的 `target` 决定** —— 一把尺子。

加成 `SKILL_ALLY` / `SKILL_GROUND` / `SKILL_ENEMY` 三个枚举值的话就有两份真相
（枚举值和技能表），而它们可以分叉。这和那个枚举顶上原来那句
「两个 bool 就有四种组合，其中『两个都开』是个说不清的状态」是同一条道理。

`target = NONE` 的技能**不进这个状态机**：点一下就放完了。

取消三条路照旧：**右键 / `Esc` / 再点一次那一格**。

### 4.2 高亮（决策 1）

高亮的是**正在施法的那个忍者**。它解决的是
「我按了技能之后视线回到战场，忘了是谁在放」——
地面技能也要它，而地面技能没有「候选目标」可高亮。

`target = ALLY` 时**另加一档**：可选目标脚下画一圈淡环。
不加的话玩家不知道能不能点已经倒下的人、能不能点自己。
这一档和施法者高亮**不同色** —— 理由和 `PBAimLines` 的 A/B/C 三色一样：
一个是既成事实，一个是等你点。

虚线跟着加一条：`PBAimLines` 现有 B（红，等你点敌人）/ C（橙，等你点落点），
加 **D（青，等你点友军）**。

### 4.3 指令卡

3×3 九格，战斗中现在只用 3 格。加上最多两个技能之后是 5 格：

```
[攻击]     [自动选敌]   [忍术]
[技能 1]   [技能 2]     [      ]
```

- 忍术留在第 2 格不动 —— 肌肉记忆。
- 格子上写**短的**：技能名两三个字 + 冷却剩余秒数。
  冷却中是灰的，不是点了没反应（后者玩家分不清「还没好」和「我点歪了」）。
- 长句进 `PBTooltip`，走已有的悬停 → `_hint` 那条路。
  提示行预算 **22 个汉字**（`PBCommandCard.HINT_BUDGET`），不够就上 tooltip。

### 4.4 buff 显示（决策 4：两样都留）

#### 先说一条几何事实：头顶放不下

```
FIELD_TOP        = 34
SPRITE_HEADROOM  = 64          ← 已经是算出来的天花板
GROUND_TOP       = 34 + 64 = 98
人物身高          = 60（M6-m 定的）
最后一排那个的头  = 98 − 60 = 38
可用             = 38 − 34 = 4 像素
```

§02 第 8 点那句「头顶名字/等级/buff」在当前几何下**做不到**，
除非改配平（压 `field_height` 或撑大 B）—— 那是数值回归的事。

#### 所以是这两处

**一、信息栏 H 的图标条**

`H_INFO = Rect2(222, 260, 168, 94)`，正文右边界在 x 偏移 162。
血蓝条现在从偏移 42 起、宽 96，右端到 138，只剩 24 像素。

**把两条从 96 缩到 76**（右端 118），腾出 118..162 共 44 像素：

```
图标条  x 偏移 122 .. 162（40 宽）
        y 偏移  20 ..  30（10 高，压在两条中间）
        4 格，10×10，pitch 10
        超过 4 个时最后一格变成「+N」
```

条从 96 缩到 76 仍然读得出比例（那是一条百分比条，不是刻度尺）。

**正文五行一行不动** —— 属性 / 力敏智 / 攻防元素 / 射程装备 / 羁绊。
M6-j 刚为第五行付过账（上下各收 2 像素买回一整行），
而 58 像素高**装不下第六行**：每行会掉到 9.6 像素，而 8 号字的行高要 11。

**二、战场上的染色**

`PBBuffBag` 里有增益就在人身上描一圈暖色、有减益就冷色，一帧一次查询。
**不占垂直空间**，所以不受上面那条几何限制。

它和图标条分工明确：染色回答「**谁**身上有东西」（一眼扫全场），
图标条回答「**是什么、还剩多久**」（选中之后才问）。

### 4.5 特效

现在是白模 + 代码画的美术阶段（`PBIconArt` / `PBWhiteModel` 那条路），
所以特效也是代码画的：

| 时机     | 画什么                                | 复用谁                                                                          |
| -------- | ------------------------------------- | ------------------------------------------------------------------------------- |
| 施法瞬间 | `skill_anims` 那一段 + 一圈扩散的环 | `PBActorSkin` 已支持；环走新的 `PBSkillFxPool`，与 `PBTelegraphPool` 同构 |
| 命中瞬间 | 目标身上闪一次色（回血用绿）          | `PBHitFeedback`                                                               |
| 持续期间 | 单位描边染色                          | §4.4                                                                           |

**特效一律不参与判定。**

## 6. 安全属性

### 落地那一刻，全部既有配平数字一个不动

**因为没有任何角色的 `skill_ids` 非空。**

和 M3.5-f 把装备交给玩家时那条「空着 = 和 M3-c 到 M3.5-e 一字不差」
完全同形，也是它敢在数值回归之前落地的全部理由。
加技能是**改 `data/`**，那时才动数字。

`test_skill_data.gd` 第一条锁着这个：空技能表的一局与不带技能系统逐字段一致。

### 批量扫描不吃技能

`PBStrategy` 里没有玩家，而技能是手动放的。
和 `_aim_policy` 一样 —— 画面走手动、扫描走自动档；
**v1 扫描那一路一个技能都不放**。给手机端做自动施法是 v2 的事，
那时它是 `PBAimRules` 的兄弟，不是第二套。

### buff 不进存档

战斗是一波一场，`PBAttacker.revive()` 每波满血满蓝复活，
所以 buff 是**波内作用域**的，不跨波、不进 §12 的存档。
尾兽冷却那种跨波的东西已经有它自己的字段（`carry_over_ticks`），
不要把 buff 也塞成跨波的 —— 那会让「这一波我身上有什么」变成一个存档问题。

### 不引入新的 RNG

三条流（gacha / quest / combat）一条都不动。技能与 buff 全部确定性，
同种子两局逐 tick 一致 —— 一条测试钉着。

## 8. 已知缺口

### 治疗在 `PBValuation` 里没有定价

一个回血技能值多少 = **它挡掉了多少伤害**，而现有估值口径里没有这个维度
（`PBValuation` 数的是 DPS 与羁绊）。

不影响 v1（扫描不放技能），但配一个治疗角色进 `data/` 的那一天，
比价会**看不见他的价值** —— 表现是模拟玩家永远不买他，
而那会让他在全部扫描结论里显示成一张废卡。归数值回归。

### 头顶 buff 图标要等几何松动

见 §4.4。压 `field_height` 或撑大 B 都改配平，归数值回归。

### 自动施法（手机端）没做

§02 的分层验收（手动比自动强 15–25%）只覆盖大招落点那一维。
技能加进来之后那条验收要不要跟着扩，得先有一批真技能才谈得上。
# 持续技能公式补充（2026-09-15）

当前伤害与术语以 [伤害计算规则.md](伤害计算规则.md) 为准。
`data/buffs.tsv` 保留 7 个必填列，可选第 8 列配置 `harm_stat`、`harm_mult` 和 `durations`。
前两项给每跳 harm 加上施加者属性项；`durations` 按等级选持续时间，支持非线性分档。
属性由 `PBHarmContext` 保存快照，实际数值落在 buff 实例，不能改写共享定义。
分级时长由 `PBBuff.duration_ticks(cfg, level)` 统一换算，敌我施法、自增益及被动触发均传递施法者等级。
首跳在一个周期后，到期 tick 包含最后一跳；同 id 刷新重新排首跳与到期，不新增叠层。

## 地面多段技能补充（2026-09-15）

`data/skills.tsv` 的额外列支持 `hits`（总段数）、`interval`（段间秒数）、`hit_radius`（独立杀伤半径）。
默认 `hits=1` 保持现有单次路径；多段目前只支持地面敌方技能，间隔至少一个 tick。
`hit_radius=0` 时，各段打原落点的完整范围；非零时，在技能范围内按等面积螺旋分布落点，每段用独立半径。
`PBSkillBarrage` 与技能栏的 `PBSkillCast` 分开保存状态，以支持冷却重置后的重叠施法；不挂目标持续 buff。
首段在施法延迟结束时结算并转冷却，其余逐 tick 到点结算；每段重新圈人和掷暴击、调用共同防御入口。
扣蓝、自身效果、召唤及全队效果仍按整次施法触发一次。施法者死亡不收回已出手序列，跨波不保留。
渲染层只读序列最后一段的落点与半径；命中播报仍经 `PBBattleLog`。
两项具体技能的原版依据、暂定时序及分布见 [伤害计算规则.md](伤害计算规则.md)。

## 自身周围控制与防御补充（2026-09-15）

`target=NONE, affects=ENEMIES` 不等于一律打全场：`radius > 0` 时以施法者当前位置为圆心，
通过 `PBSkillRules.land_on_field → land` 共用范围、控制、位移与目标上限；`radius=0` 保留全场路径。
`on_self` 仍在指令发出时生效，`on_hit` 在落地时挂给命中目标。
无直接伤害的控制 / 防御技能用 `power_mult=0`，通过效果提供功能；不能添加原版未注明的伤害。
防御与忍术抗性分别使用 `defence` 和 `ninjutsu_resist`；不是 `damage_taken` 的全类型减伤。
非线性控制和增益时长共用效果表 `durations`；既有敌我入口按施法者等级读取。

## 分级召唤与追击补充（2026-09-15）

技能额外列新增 `summon_growth`、`summon_focus`。攻击继承统一为
`summon_power + summon_growth × (等级 - 1)`，通过 `PBSkill.summon_power_at(level)` 读取。
`summon_power_scale` 羁绊补丁同时缩放两项，普通施法、受击召唤和说明卡共用等级口径。
`summon_focus=1` 只用于锁定敌人的召唤技能；落地前目标失效则空放。
召唤物沿用 `forced_target` 记录目标，`focus_named_target` 使其在有效目标未进射程时继续追击而不攻击路边敌人。
走位、开火和瞄准共用既有索敌入口；目标失效后回落到普通索敌。
召唤物继承本体移动范围，散场和复用时清理追击 / 起手状态，数组仍在开波时定长预留。
具体原版依据及尚未还原的忍犬独立属性见 [伤害计算规则.md](伤害计算规则.md)。

### 临时反弹（2026-09-16）

`reflect` 为己方持续效果的加法量，基础与成长必须是非负有限数；配置在其他效果档或敌方效果时加载报错。
`hurt_ally` 在扣血及受击触发之前快照当前比例，近战与弹道统一结算；查询时判断到期，不依赖清理时机。
同 ID 整份覆盖，刷新持续时间，不累加重复施放。伤害基数及防御处理见《伤害计算规则》的神罗天征小节。
### 原地连击与忍术免疫（2026-09-16）

自身周围（NONE）可配置连击与首次命中延迟，不允许分散落点。圆心取施法者位置；死亡或离开圆心终止，地面连击不受此限制。
`channel` 己方持续效果同时约束移动、普攻与 can_cast；`ninjutsu_immune` 在统一 hurt_ally 入口按伤害类型归零，不把七属性中的物理与体术混用，不用抗性模拟免疫。
上述窗口键只接受己方持续效果，基础值和成长须有限且非负。技能补丁 `gather` 接入既有圆心聚拢读点，因此多段技能每跳都重新聚拢。
### 阵亡移动后施法（2026-09-16）

技能 `death_move_ticks`（TSV `death_move` 秒数）使阵亡技能延迟到死亡 tick + 指定窗口落地。
致命命中只记录来源位置快照；无来源时原地等待。移动和待落地状态独立于 alive，不能借此重新启用普通移动、普攻或受击。
`revive` 清除窗口并 reset 阵亡技能状态。未配置窗口的阵亡技能仍立即结算，详细缺省行为见伤害规则。
### 沉默与敌方主动技能（2026-09-16）

`silence` 为敌方持续效果，由 PBEnemyAbilityRules.advance 在主动施法入口读取；不能放入己方或瞬间效果。
普攻入口不读取 silence，无论普攻是体术还是忍术。主动技能和普攻独立冷却，沉默不消耗技能冷却，眩晕拦两者。
PBEnemyAbility 资源描述单体直伤；PBWave.abilities 注入战斗，spawn 验证配置并重建各敌人的冷却状态。空数组保持旧波次行为。
敌方技能与普攻共用 PBCritRules.enemy_hit 和 PBStrikeRules.hurt_ally，避免新增一套暴击、防御和阵亡结算。
目前只有框架和真实模拟测试接通，生产怪物技能分配尚未接入；后续不应把测试技能直接当作最终怪物配置。
### 每波首次施法加伤（2026-09-16）

羁绊 first_cast_attack 配置总攻击力系数；建队后生成 first_cast_damage，施法状态 first_cast_spent 保存本波机会是否用过。
单段即时命中技能落地时取出一次额外伤害，和基础伤害一起进入已有分型结算。取值后即消耗，空放不退；ready_at 重置不修改次数，整波 reset 才恢复。
当前仅用于青春的力量的首次木叶刚力旋风，未实现通用“首次触发另一个完整技能”的替换或连锁系统。
### 锁定敌人的范围技能与主目标效果（2026-09-16）

ENEMY 且 radius > 0 的非弹道技能在 land_on_enemy 以目标当前坐标为圆心走统一范围命中。目标失效则空放。
on_hit 施加范围命中效果，on_target 单独施加主目标效果；target_effect_area 羁绊补丁可把后者扩展到范围。
效果名单在击退前确定，伤害后只给存活目标挂效果；锁定的主目标不被周围击退扫走。on_target 参与加载校验、数组克隆和说明生成，不支持弹道或零半径技能。

### 分阶段、直线与羁绊追加命中（2026-09-16）

- `on_start_target` 仅用于有延迟的非弹道 ENEMY 技能，起手只给主目标挂一次敌方持续效果；落地重新核实目标存活。空放不把伤害改投其他敌人。
- `airborne` 配合定身 / 眩晕，状态保存 `applied_at`；EnemyPool 根据 tick 进度抬高精灵，地面位置、阴影和命中坐标不变。
- `blink_to_target` 在有效目标的伤害结算前移动施法者；锁定零半径技能支持存活主目标击退，范围技能仍不推主目标。
- `line_length` 非零时由 PBSkillArea 统一计算从 cast.origin 发出的矩形；radius 为半宽。瞄准 / 预示与命中复用同一几何，施法后原点和方向固定。
- `echo_delay_ticks` 从施放时刻计时，须晚于首击，仅用于单段地面圆形敌方技能。复制纯伤害到独立连击排期，`echo_radius_scale` 扩缩第二次范围，不复制控制与位移。
- `hit_step` 非零时，自身周围多段技能改为固定起点朝 +X 蔓延，出手后不依赖本体存活 / 位置。零值保留原地持续施放的取消规则。羁绊通过 hits_add / hit_interval_seconds / hit_step_set 配置段数、间隔和推进距离。
- 二次命中及蔓延复用 PBSkillBarrage，耗蓝 / 冷却只在原施法处理；重复施法使用独立实例，结束实例可复用，换波清空。
- `on_hit_harm_scale` 先深复制带 harm 的命中效果，再缩放伤害基数、成长及属性项；控制 / 时长 / 其他效果不变，禁止直接改共享 PBBuff 定义。

### 锁定技能追加目标（2026-09-16）

`PBSkillTargets` 集中选取名单：主目标必须仍有效，优先主目标，然后按距主目标的距离、槽位升序补足。
只选已出生存活敌人 / 可被选中的友方，不重复、不从追加目标向外连锁搜索。友方即时、敌方即时与双方弹道共用这一规则。
零杀伤半径的锁定技能 max_targets=0 等价于基础单体 1；targets_add 在此基础上相加。范围技能的 0 仍是不限，增加目标不能反而限制人数。
`extra_target_radius` 为独立搜索半径，羁绊键 extra_target_radius_set；锁定多人必须配置正有限范围。当前不支持与延迟阶段、闪烁或召唤组合，加载器及真实补丁测试负责拦错。
名单在即时结算 / 弹道发射时确定；每个弹道保持自己的目标，飞行途中目标死亡则该发消失，不补选其他目标。
一次施法共用一次暴击，耗蓝、冷却、自身效果仍只处理一次。弹道池不足时按名单顺序尽量发射，优先主目标，未发出的部分空放，不瞬间补伤。

### 禁攻与仙属性易伤（2026-09-16）

`disarm` 为敌方持续禁攻，PBEnemy.ready_to_fire 统一拦近战 / 远程、体术 / 忍术普攻；不影响移动或 PBEnemyAbilityRules 的主动施法。
`sage_hurt_scale` 为敌方持续倍率，与 hurt 相乘，默认 1；只按伤害事件的 SAGE 属性生效，不按伤害类型或角色属性分支。
PBEnemy.element_hurt_scale 是唯一查询点，take_damage 和 damage_to_kill 接受伤害属性，均在护盾前计倍率；未给来源属性的旧调用默认物理属性。
混合周期伤害必须先逐份调用同一查询点再合计，不能在统一扣血时才猜整个总量的属性。PBHarmContext.damage 返回值已含属性易伤，通用 hurt / damage_taken 与护盾仍在 take_damage；这一类调用不能再传同一属性，避免重复乘算。
新增两个键只允许敌方持续效果，基础与成长须有限且非负；DISARM 不替代既有 STUN / SILENCE。


### 弹道命中后的周围禁锢

技能补丁键 `impact_hold_radius` / `impact_hold_seconds` 同时配置，且只允许锁定敌人的技能弹道。由 `PBSkillImpact` 校验与结算，`PBShotRules` 命中主目标后调用。范围中心取命中时的主目标位置，排除主目标、死亡和未出生敌人；不复制伤害 / 主目标效果，不连锁。相同技能的附加禁锢使用稳定效果 ID，重复施法刷新，不叠加。本规则不包含施法者引导中断机制。

### 锁定控制的持续施法

`channel_control` 只允许单体敌方弹道，携带一份 DURATION 禁锢效果。`PBSkillOrders.issue` 建立独立 `PBSkillChannel` 凭据，弹道关联它，命中后主目标及附加周围控制共享凭据。施法者、主目标和主控制槽位用弱引用，不形成 RefCounted 引用环。

`PBSkillChannel.blocked` 统一处理旧 CHANNEL 效果及新引导，供自主移动、普攻、手动施法和自动大招读同一规则。`PBBuffState.is_live` 除时长外查询凭据；中断即失效，不等待 sweep。效果槽复用必须清除 channel，主控制槽被覆盖后原引导失效，新的引导不会被旧来源取消。每个模拟只按递增 tick 查询，不能先查未来再退回当前。

死亡 / 重生、眩晕、沉默、主目标失效、主控制过期 / 清除 / 覆盖终止引导；弹道出膛失败也终止。引导不退蓝、不恢复技能冷却。周围控制依赖引导是本次实现约定，主动取消按钮、距离断链和专用表现暂未实现。
### 远程基础攻击被动光环

技能字段 `ranged_attack_aura` 大于 0 时为常驻光环，数据要求 NONE / ALLIES、正范围、无耗蓝、无直接伤害及命中 / 自增益效果；主动施法入口拒绝它。羁绊键 `ranged_attack_aura_set` 设置倍率，说明按百分比展示。

`PBAllyAuraRules` 在模拟建立时安装来源弱引用，按出手时距离、来源与受益者可被选中状态查询，同类取最高。它不写回攻击属性或效果袋，因而离圈 / 来源死亡不需要回滚。`PBStats.base_atk` 与 `PBAttacker.base_attack` 保留直接攻击词条前的基数，`ranged_attack` 来自真实射程档，不能拿七种攻击属性猜近战 / 远程。

普攻在统一 `strike_for` 接入；智力型忍术普攻排除。攻击型技能使用 `attack_formula_scale` 折算临时增量，效果来源快照同步攻击属性。召唤物继承基数而非已经吃到光环的输出；克隆与新模拟重新连接来源。光环可视范围和动态攻击面板另列后续。
## 三围转化与献祭（2026-09-16）

`PBAttributeProfile` 保存战斗单位的角色、等级、星级和属性词条基线；`PBAttributeRules` 通过现有 `PBStatRules.of` 重算三围赠送后的派生值。生命和蓝量保留当前比例，攻击保留已折算的属性克制 / 队伍倍率，护甲、攻速、基础攻击、智力型普攻及所有普通 / 阵亡技能公式同步更新；出手和技能冷却不重置。已飞出的直接伤害不回写。

`PBSacrificeRules` 按源脚本对整数三围计算 `floor(floor(三围×0.99)×(0.10+0.03×等级)×倍率)`，向选中的一至两名其他忍者赠送相同增量；召唤物不能成为目标。施法者三围不减少，5 秒后直接阵亡，绕过闪避、护盾、免疫、不死和普通伤害重生；通过统一阵亡记账触发阵亡技能。提前死亡不重复记账，赠送不被撤销。

三围增量只属于本波 `PBAttacker`，不修改 `PBUnit` / `PBCharacter` / 原始效果资源；下一场模拟开始恢复基线，克隆使用独立 profile 和技能定义。生命 / 蓝量保留比例、追加目标排除施法者为本项目实现约定；原版追加目标筛选只明确排除主目标。

## 2026-09-16：技能附加招式与移动波

补充（第 15–16 批）：技能 `mp_cost_levels` 为完整逐级耗蓝，技能表 `cost_levels` 以逗号分隔且首项等于基础耗蓝列。`PBSkillCostRules` 统一门槛、实际扣除与显示，克隆时独立复制数组；被动光环与附加招式不允许隐藏逐级费用。五影尘遁使用 `rebate_delay_seconds` / `rebate_mana_scale` / `rebate_cooldown_seconds` 三个成员补丁，`PBSkillCast` 记录本波待返时间及金额，`PBSkillRebateRules` 在落地安排、每 tick 消费一次、换波清零。不是普通治疗效果，也不占 BUFF 槽位。

主技能只扣一次蓝、开启一次冷却。附加招式从真实目标位置或施法者位置建立独立 `PBSkillBarrage`，锁定当次位置与伤害，源死亡 / 移动不收回。`radius_growth` 表示各次实际命中半径增加值，不等于日晕舞逐段选一个未命中目标。

移动波使用 `PBTravelWave`：`travel_step` 为每步位移，`wave_count` / `wave_interval_ticks` 控制独立波数量及发射间隔，`fan_spread_degrees` / `fan_steps` 控制离散随机扇面。每道保存已命中槽位，不能因前进重复伤害；各道可以重复伤害同一敌人。发射时朝当前攻击目标的方向，加战斗随机流产生的偏角；没有随机流时偏角为零。原版按实际单位朝向，这里按逻辑攻击目标方向适配。渲染读取各波真正的位置和半径，以元素颜色显示，不代替后续专用特效。

`self_duration_scale` 复制自身效果定义并缩放基础时长 / 分级时长表，不改共享 BUFF，也不缩放效果量。
