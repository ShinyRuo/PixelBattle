## 怎么重新量

四份表就是全部事实，`.tres` 是它们生成出来的（别读 `.tres`）：

| 问题 | 去哪 |
|---|---|
| 谁有哪几个技能 | `data/skills.tsv` 第 2 列（角色键）、第 3 列（技能名） |
| 谁有哪些被动 | `data/roster.tsv` 第 16 列 |
| 羁绊给谁发了什么 | `data/bonds.tsv` 第 5 列（载体）、7 列（成员效果）、8 列（技能补丁） |
| 效果词汇表 | `data/buffs.tsv`；键的定义在 `PBBuffRules` / `PBPassiveRules` / `PBSkillPatchRules` |
| 原版有什么 | 那份解包文档，技能条目的形状是 `**<档>-<角色>-<技能名>**　\`Axxx\`` |

**别拿技能名去和原版对**：标点不一样（`鲛肌·削灭斩` vs `削灭斩`），
而且一批原版技能在我们这里是**被动**不是技能（写轮眼、削灭斩、风切、柔拳、骨拔、
永恒万花筒、轮回眼、扭曲攻击），按名字对会报出一个假的缺口。
**按角色对，或者直接数「谁手上什么都没有」。**

后两条是**原先的分诊清单里也漏掉的**。溅射范围为此加了一个读点：`splash_radius` 存原版码数，
换算只在 `PBStrikeRules.splash_reach` 一处（同射程的 `PBSimConfig.reach_of`），没配的仍是默认 0.06。

> **教训是一条结构性的**：**一份「缺什么」的清单和一份「有什么」的词汇表
> 是同一件事的两半，而它们分在两个文件里，改一边不会碰另一边。**
> 同这个项目反复踩的那条「断言写的是当下的数据状态」——
> 只是这次载体是文档不是断言，所以连红都不会红。
>
> **补它的办法**：把这份清单变成一张表 + 一个生成器（同名册 / 羁绊 / 技能那三套），
> 让「卡点」那一列去查 `PBPassiveRules.is_known` 等等，
> **卡点已经进了词汇表就直接报错退出**。那是另一步，还没做。

## 2026-09-15 伤害公式核查（代码审查，尚未修正）

玩家明确的目标：物理普攻 / 体术按攻击力与相应属性计算，吃护甲、物理暴击及物理 / 体术增伤；绝大部分忍术技能及忍术普攻按智力 × 系数计算，吃忍术抗性、忍术暴击、忍术增伤及穿透，不吃护甲。

核对现有代码后，批十五的“分型完成”仅能代表部分结算环节，不能代表完整公式符合上述目标：

- 忍者打敌人的护甲 / 忍术抗性、两类暴击、忍术增伤与穿透已分流；鼬配置为忍术普攻、忍术暴击率 +15%。穿透按比例削减抗性，例如 40% 抗性遇到 50% 穿透后剩 20%。
- `PBCombatRules.skill_damage` 仍统一取 `unit.power(cfg)`（攻击力 × 攻速）乘技能、克制和队伍倍率，没有按体术取攻击、忍术取智力。忍术普攻仍以攻击力为基数，仅切换伤害类型；普攻攻击力按角色主属性派生，并非统一按敏捷。
- 增伤词条语义尚未完整分开：`damage_bonus` 当前是普攻增伤，`PBAttacker.strike_for` 对两类普攻都乘它；`PBCritRules.hit` 对体术技能不乘它。若以此承载物理 / 体术增伤，会出现忍术普攻也受益、体术技能不受益。后续须明确通用、普攻专用、物理、忍术增伤，不能直接把所有旧词条改成物理增伤。
- 敌人攻击目前固定物理类型，`PBStrikeRules.hurt_ally` 统一走忍者护甲；敌人忍术攻击及忍者忍术抗性的对应结算尚未接通。
- 持续伤害与即时 `HARM` 效果走无施法者的忍术减伤路径，不继承施法者的忍术增伤、暴击及穿透；应作为单独效果规则明确。

本次只核查源码与配置并记录差异，未修改战斗实现，未运行回归或深度配平。下一步优先修正伤害公式与词条分类，再扩展敌人主动技能；既有伤害分型测试不能代替属性基数和增伤隔离测试。
