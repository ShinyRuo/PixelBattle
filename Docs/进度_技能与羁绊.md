# 进度：角色技能与羁绊

**这份文档回答两个问题：做了哪些、还要做哪些。**
量于 **M12-c4 批三之后**（致命伤与阵亡触发），对着
[Docs/原版数据_忍法战场v1.5.80.md](原版数据_忍法战场v1.5.80.md)。

> **⚠ 这份是手写的快照，不是生成的 —— 它会过期。**
> 这个项目为「记录写的是当下的数据状态」付过很多次代价，所以先把话说在前面：
> 下面每一个数都标了**怎么重新量**，而「还缺什么」那一半标了
> **是对着哪一版词汇表分的诊**。
>
> **本文档最大的一条发现曾经正是一份过期的分诊**：M12-c1 判定「缺读点」的那批技能里，
> 有一批在 c2 / c3 / e1 / e2 造出机器之后就能做了，而表里还写着缺读点。
> 那一批已经补上（见第三节），教训留着。

## 怎么重新量

四份表就是全部事实，`.tres` 是它们生成出来的（别读 `.tres`）：

| 问题 | 去哪 |
|---|---|
| 谁有哪几个技能 | `data/skills.tsv` 第 2 列（角色键）、第 3 列（技能名） |
| 谁有哪些被动 | `data/roster.tsv` 第 16 列 |
| 羁绊给谁发了什么 | `data/bonds.tsv` 第 5 列（载体）、7 列（成员效果）、8 列（技能补丁） |
| 效果词汇表 | `data/buffs.tsv`；键的定义在 `PBBuffRules` / `PBPassiveRules` / `PBSkillPatchRules` |
| 原版有什么 | 那份解包文档，技能条目的形状是 `**<档>-<角色>-<技能名>**　\`Axxx\`` |

**别拿技能名去和原版对**：标点不一样（`鲛肌·削灭斩` vs `削灭斩`），
而且一批原版技能在我们这里是**被动**不是技能（写轮眼、削灭斩、风切、柔拳、骨拔、
永恒万花筒、轮回眼、扭曲攻击），按名字对会报出一个假的缺口。
**按角色对，或者直接数「谁手上什么都没有」。**

所以「38/44 组」听起来盖了八成，而真正的进度是那 49%。

## 三、分诊过期的那批：已补上（M12-c4 批一）

M12-c1 逐条判过哪些技能缺读点，而 c2（致盲 / 晕眩 / 被动通道）、c3（召唤）、e1 / e2
把机器造出来全在那之后 —— 分诊没有跟着更新，表里一直记着一批已经不成立的降级。
这一批补完了，**落成的形状和做不了的那一半**：

| 原版原文 | 落在哪 | 做不了的那一半 |
|---|---|---|
| 迪达拉·黏土蜘蛛「召唤 1~10 只自爆，300 点小范围伤害」 | `clay_spider`，点地面 AOE（不是召唤物），范围 0.10 | — |
| 迪达拉·起爆黏土·巨鸟「每次攻击对目标及周围 275 码额外伤害」 | 被动 `splash=0.5;splash_radius=275` | 主目标本身不多吃那一笔 |
| 阿斯玛·火遁.灰积烧「扇形伤害 + 致盲 2.5 秒」 | `ash_burn`，点地面圆（玩家定的），`asuma_ash`：`enemy_hit_scale=0` | 扇形 |
| 飞段·血腥三月镰「35% 分裂」+ 咒术.死司凭血「反弹 25%」 | 被动 `splash=0.35;splash_radius=250;reflect=0.25`；射程 245 在名册「射程」列 | 致命伤不死 |
| 奇拉比·七刀流「暴击率 [10+2x等级]%，暴伤只有 150%」 | 被动 `crit_chance=0.20`（取 5 级）。**暴伤不用写负数**：`PBCritRules` 的基础暴伤就是 150% | 每下 +8%、暴击后归零（叠层） |
| 〔终成眷属〕雏田「回天覆盖范围 +100%」 | `hinata:palm_rotation:radius_scale=2` | 仙人鸣人那半（全属性 + 蛙组手） |
| 〔绝牛雷犁热刀〕奇拉比「普攻暴击伤害 +75%」 | 成员效果 `killer_bee:crit_damage=0.75` | 跟着艾一起跳 |
| 〔晓之四象〕迪达拉「黏土蜘蛛伤害 +35%」 | `deidara:clay_spider:power_scale=1.35` | 攻击时必定召唤蜘蛛 |

后两条是**原先的分诊清单里也漏掉的**。溅射范围为此加了一个读点：`splash_radius` 存原版码数，
换算只在 `PBStrikeRules.splash_reach` 一处（同射程的 `PBSimConfig.reach_of`），没配的仍是默认 0.06。

> **教训是一条结构性的**：**一份「缺什么」的清单和一份「有什么」的词汇表
> 是同一件事的两半，而它们分在两个文件里，改一边不会碰另一边。**
> 同这个项目反复踩的那条「断言写的是当下的数据状态」——
> 只是这次载体是文档不是断言，所以连红都不会红。
>
> **补它的办法**：把这份清单变成一张表 + 一个生成器（同名册 / 羁绊 / 技能那三套），
> 让「卡点」那一列去查 `PBPassiveRules.is_known` 等等，
> **卡点已经进了词汇表就直接报错退出**。那是另一步，还没做。

> 伤害 —— 加一个抗性字段之后没有任何一条伤害会去查它，那正是「配了不生效」，

## 六、建议的下一步

**c4 批一、批二、批三已经做完**（分诊过期的那批；血量阈值触发；致命伤与阵亡触发）。

批二落成的形状：名册被动列 `low_hp=阈值;on_low_hp=<效果键>`，判据在
`PBStrikeRules.wound_ally`（忍者掉血的唯一落点，敌人攻击与自身掉血都走它），一波一次。
顺带进来三个效果键：`heal_max`、`drain_max`（己方自身掉血，走记账）、`defence`。

批三落成的形状：
- **致命伤**：名册被动列 `on_lethal=<效果键>`，一波一次。`PBAttacker.take_damage` 在那一下会打死他时让血停在 1、
  记一笔，`wound_ally` 接着挂效果（挂效果要配置，`take_damage` 手上没有）。效果键 `undying`（血停在 1）。

  `PBBattleSim._fire_death_casts` 同一 tick 以尸体为落点走 `_land_skill`，和手动施法同一条路。

  按了扣蓝进冷却、**谁身上都没有效果** —— `_land_skill` 里那两档只处理了打敌人。现在走 `PBSkillRules.land_around_allies`。
