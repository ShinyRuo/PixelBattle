# 素材规格 —— 战场形象

> **2026-09-17 新需求**：忍者增加专属六帧施法动作，第 4 帧释放，不受攻速影响；召唤物独立配置待机 / 移动 / 攻击 / 死亡四态及远程子弹。当前素材与运行链尚未完成该升级，详细规范与待确认项见 [技能与BUFF系统](技能与BUFF系统.md) 顶部。下文旧的“三段”等表述不代表新增施法动作已经具备。

**给画图的人看的一页。** 这里只管**战场上那个会动的小人**；
卡面头像、UI 图标、场景背景是另外的规格，还没开。

对应代码：[`PBActorSkin`](../src/view/actor_skin.gd)（一份素材的全部约定）、
[`PBWhiteModel`](../src/view/white_model.gd)（现在顶着的白模，可以当参考实现看）。
放哪儿：[`data/actors/`](../data/actors/README.md)。

## 0. 一句话

**像素风、侧面视角、单人立绘动画**，风格参照 flash 游戏《死神 VS 火影》；
战场的镜头是《DNF》《Idle Champions》那一档 —— **正侧面 + 约 45 度俯视**。

## 1. 视角：人是正侧面画的，地面是压扁的

**人物本身按纯侧面画**，不要画俯视角度的头顶或肩线。
俯视只体现在**地面**上：游戏把纵深方向压成了 `sin 45° ≈ 0.707`
（[`PBLayout.Y_SCALE`](../src/view/layout.gd)），所以

- 战场上的一个**圆**（射程、忍术落点）在屏幕上是一个**扁椭圆**
- 一个单位往里走一格，屏幕上只往下挪 0.707 格

这件事**已经由引擎做掉了**，素材不要自己画透视。素材唯一要配合的是
**脚底那个点**（见下一节）—— 前后关系、影子、射程圈全部挂在它上面。

## 2. 画布与锚点（最要紧的一节）

**M6-m 起分两档，而两档的画布尺寸差三倍。M6-n 起只出高清档**
（像素档那一列留着当参照，不再产新素材）。先看这张表，再看下面
「哪一档」那一节 —— 拿错档的表现是人有三个身位那么高，或者还是糊的。

|              | 忍者 · 高清档（现在的真素材） | 忍者 · 像素档 | 小怪（白模）    |
| ------------ | ----------------------------- | ------------- | --------------- |
| 屏幕上多高   | **60 px**                     | **60 px**     | 20 ~ 24 px      |
| 贴图里多高   | **180 px**（= 60 × 3）        | 60 px         | 同左            |
| 画布         | 宽随内容，**高 ≤ 186**        | 高 ≤ 62       | **36 × 36**     |
| `pixel_scale`| **1/3**                       | 1             | 1               |
| `smooth`     | **true**（线性 + mipmap）     | false（最近邻）| false          |
| 半透明边缘   | **要**（软边就是这一档买的）  | 不许          | 不许            |
| 脚底锚点     | **画布底边中点**              | 同左          | **画布底边中点**|
| 每段每帧尺寸 | **必须完全一致**              | 同左          | 同左            |

> 画布**宽**没有上限，按内容走（出拳那一帧比站着宽得多，带武器的角色更宽）：
> 现有三个真素材是 260×186 / 230×186 / 360×186。要紧的只有两条：
> 同一个角色的每一帧尺寸完全一致，以及脚底落在底边中点上。

### 60 是天花板，不是一个还能再调的数

战场那一块（B 框）高 **220 px**，里面装两截：

```
头顶余量  ≤ 64   ← 站着的人画在这里面（PBLayout.SPRITE_HEADROOM）
地面带     156   ← 500 × 0.44 × sin45°，脚能站的那一段
           ───
           220
```

画布要装下人加一点留白，60 + 2 之后 64 里就剩不下什么了。再往上只有
两条路，**两条都改配平**：压 `field_height`（地面带变窄，开战站位跟着变），
或者把 B 框本身撑大（上面是顶栏、下面是底栏，各只剩几像素）。

### 但一帧最高能画到 96（M9-i）

上面那个 64 管的是**站着的人**。抬手、跳起来那几帧本来就比站姿高 ——
实测 29 套素材里 **10 套顶到了旧上限**（naruto / lee / enemy_earth_ranged
三套是真把头切了，怪的体型更容易顶天）。

所以 M9-i 把两个概念拆成了两个数：

| | 是什么 | 值 | 动它要付什么 |
|---|---|---|---|
| `PBLayout.SPRITE_HEADROOM` | 地面带从 B 框上沿让出多少（**排版**） | 64 | 和 `field_height` 抢地方 → **改配平** |
| `PBActorForge.CANVAS_CEILING` | 一帧最高能画多高（**素材**） | **96** | 抬手那几帧可能压到顶栏 |

契约因此从「任何一帧都不许越界」放宽成
**「站姿保证不越界，抬手那几帧允许探出去一点」**，配平一分没动。

**为什么是 96 不是 128**：最上面那条泳道的脚落在 `GROUND_TOP` = 98，
所以最坏情况下头在 `98 − 上限`：

```
上限  64（旧）→ 头在  34   正好贴着 B 框上沿
上限  96（现）→ 头在   2   还在屏幕里，抬手那两帧会压住顶栏的字
上限 128      → 头在 −30   戳出屏幕外，顶栏整个被盖住
```

`GROUND_TOP` 就是这个数的硬上限，`test_actor_forge.gd` 钉着它。

### 它比战场的纵深「装得下」的大出两倍，是有意的

屏幕上的纵深只有 155 px，而 `ally_lane` 把**全部上场的人**平铺在这一段里
—— 站 7 个人时每两条道只隔 22 px，而人有 60 px 高。也就是说
**同一列里的人一定会互相挡住一截**，这是几何，不是可以调好的东西。

挡一截换来的是「看得清」：这个数走过 18 → 27 → 41 → 60，
四次的依据各不相同（挤不挤 → 脸认不认得出 → 在 640×360 里够不够一个量级
→ 玩家试玩后说「人物有点小」）。挡的关系永远是对的（近的挡远的，
引擎按脚底 y 排序），**而「几个人」这个读数由描边保住** —— 见下面第 6 节。

**白模没有跟着抬**（41，玩家定的「白模先不动」）。它跟不了：那块画布是
方的（手臂要摆得开），按同样比例放到 60 要 79 见方，装不进 64 —— 白模
能到的最高是 `64 × 41/54 ≈ 48`。所以真素材和白模现在差一截，那是已知的。

**脚底锚点是整份规格里最要紧的一个数。** 引擎按「谁的脚更靠下」决定谁画在
前面，锚点差一格，这个人和别人的前后关系就错一档 —— 而画面上一切看起来
都很正常，只是偶尔有人被莫名其妙地盖住。

- 默认锚就是**画布底边中点**，按这个切图最省事
- 实在对不齐（比如人物是踮脚或飞行的），在 `.tres` 里填 `foot_offset`
  指出脚底在画布上的像素坐标，**不要靠留白去凑**
- **同一份素材的所有帧尺寸必须一样**（代码只读第一帧算锚点，
  不一样的话人会在动画里上下跳）

### 哪一档：「更大」和「更清晰」M6-m 之后是两个旋钮

**坐标系永远是 640 × 360**，窗口再大也只是把它放大。但
`stretch/mode` 是 `canvas_items`（M6-d），也就是说
**坐标系是 640×360，光栅化却发生在窗口的真实分辨率上** ——
文字在 1080p 上清晰正是这条。于是：

| 窗口                | 倍数    | 60 px 高的忍者占多少**真实**像素 |
| ------------------- | ------- | -------------------------------- |
| 1280×720            | 2×      | 120 px                           |
| **1920×1080**       | **3×**  | **180 px**                       |
| 2560×1440           | 4×      | 240 px                           |

**像素档**的贴图只有 60 px 高，所以 1080p 那 180 个真实像素里只装得下
60 个色块 —— 放大的是块，不是细节。

**高清档**把贴图做到 **180 px**（正好是 1080p 那一档），`pixel_scale` 填
`1/3` 把它缩回 60 逻辑像素，**缩小交给 GPU**。1080p 下是 1:1，
一个像素都不浪费也一个都不缺。

> 所以现在：**画多大 = `TARGET_HEIGHT`（60，屏幕上的事）**，
> **画多细 = 贴图倍数（3，清晰度的事）**。M6-l 之前两者是同一个数，
> 那时才有「想要更精细只能连着更大一起要」这句话。

**这一档的代价是它不再是像素画**：边缘是软的、颜色是连续的，
而屏幕上其余全部东西（面板、卡面、白模、克制亮边）都是硬边像素。
这是一个美术方向的取舍，玩家 M6-m 拍板要高清档。

## 3. 朝向：只画一边

**只需要画朝右（或者朝左）的一套，另一边由引擎水平翻转。**
在 `.tres` 里用 `source_faces` 说明你画的是哪一边，就这一个字段。

- 忍者默认朝右（敌人从右边来）
- 小怪默认朝左

**不要为了「翻转会让左右不对称的元素跑到另一边」去画两套。**
像素风这个尺度看不出来，而两套素材意味着两倍的工作量和一份永远会
慢慢分叉的对照关系。

## 4. 三段通用动画

每个角色**必须**有这三段。缺了不会报错，但那个人会卡在待机上。

| 段名       | 帧数  | 建议帧率    | 循环         | 说明                                                         |
| ---------- | ----- | ----------- | ------------ | ------------------------------------------------------------ |
| `idle`   | 2 ~ 6 | 4 ~ 6 fps   | 是           | 呼吸、衣角。**幅度要小** —— 一屏十几个人一起晃会很吵 |
| `run`    | 4 ~ 8 | 10 ~ 12 fps | 是           | 战场上的移动是小幅前压/后撤，不是冲刺                        |
| `attack` | 3 ~ 8 | 12 ~ 16 fps | **否** | 见下                                                         |

可选两段：`cast`（放忍术的施法姿势，没有就用 `attack`）、
`dead`（倒地，没有就用 `idle` 压暗）。

### `attack` 的两条硬约束

1. **第一帧就是出手瞬间。** 动画由「这一 tick 打出去了」触发，
   伤害在那一刻已经结算完了。所以**起手动作要短**（0 ~ 1 帧），
   收招可以长 —— 反过来画的话，玩家看到的是「先掉血、后挥刀」。
2. **播放速度由引擎重算，不由帧率决定。** 每个角色的出手间隔是数值定的
   （攻速 0.85 ~ 4 次/秒，差五倍），引擎会把这一段拉伸或压缩到正好占满
   一个间隔（[`PBAllyPool._fit`](../src/view/ally_pool.gd)，夹在 0.2× ~ 3× 之间）。
   所以**按自然的速度画就行**，不用去猜这个角色攻速多少。

## 5. 忍术动画（逐角色）

每个角色的忍术各画各的，段名自取，在 `.tres` 的 `skill_anims` 里
写成 `{忍术 id: 段名}`。**不循环**，帧数不限。

没配的忍术退回 `attack` 段 —— 所以**忍术动画是加分项，不是拦路项**，
一个角色可以先只交三段通用的。

## 6. 颜色与描边

**真素材自己定颜色**（`.tres` 里 `tint_by_element = false`）。
白模那一版是纯白 + 代码按属性染色，那是权宜之计，不是风格要求。

两条硬约束：

1. **必须有深色描边，绕整个剪影一圈。** 这不是风格，是**「场上有几个人」
   这个读数的唯一载体** —— 第 2 节说过同一列的人必定互相挡住一截，
   没有描边的话七个人在屏幕上就是一根实心色条，玩家数不出几个人，
   也点不中中间那个（实测截图）。
   **像素档 1 px，高清档 3 px**（贴图倍数是 3，要的是屏幕上看着一样粗）。
2. **去色之后仍要能只凭剪影认出是哪一系小怪**（§02 的验收项）。
   只管敌人，忍者不受这条限制。

**描边是压暗现有像素，不是往外扩一圈** —— 扩出去等于把身高抬高 2 px，
而身高是第 2 节那个定死的 60（画布上限 96 管的是抬手那几帧，不是站姿）。

色阶：像素档每种材质最多 3 个（降到几十个像素之后渐变会糊成噪点）；
高清档不受这条限制 —— 那一档本来就是连续色。

## 7. 导出与命名

- 格式：**PNG**，透明背景。半透明边缘：**像素档不许，高清档要有**
  （见第 2 节那张表 —— 软边正是高清档买的东西）
- 一段一张横向序列图，或者一帧一张都行 —— 最后是在 Godot 编辑器里
  拼成 `SpriteFrames`，切图方式不影响结果
- 文件名：`<actor_key>_<段名>.png`，例如 `naruto_attack.png`
- `actor_key` 用小写英文 + 下划线，**不要用角色的中文名**
  （§14 铁律 5：代码和资源里不出现角色名字符串，显示名走语言表）

## 8. 交付前自查

- [ ] 每一段的每一帧，画布尺寸都一样
- [ ] 人物的脚踩在画布底边上（或者已经填了 `foot_offset`）
- [ ] 只画了一个朝向，并且在 `.tres` 里说明了是哪一边
- [ ] **有深色描边**（像素档 1 px / 高清档 3 px）
- [ ] `attack` 的第一帧就是打出去的那一下
- [ ] `idle` 的幅度小到十几个人一起播也不吵
- [ ] **档位对得上**：高清档 `pixel_scale = 1/3` + `smooth = true` +
      贴图 180 高 + 半透明边缘；像素档全部相反。
      **混错的表现是人有三个身位那么高，或者还是糊的**
- [ ] 画布高度没超过 62（像素档）/ 186（高清档）——
      超了会被 `PBActorForge` 压回去，**被切掉的是头**（脚坐在底边上）。
      它会说出来（命令行一句红字、插件状态栏标黄），但画布、坐标、锚点
      全部看起来完全正确，所以别只看那几个数

**装进游戏之后开预览台再过一遍**：

```powershell
F:\Godot_PJ\_engine\4.7.2\godot.exe --path . res://scenes/actor_lab.tscn
```

（VSCode 里 `F5` → 「Godot: 战场形象预览台」。）

它把上面这份清单里**看不出来的那几条**变成屏幕上的读数：放大到 8 倍、
一段只播一段、画出画布框和脚底十字，信息栏直接写着「这张皮装上了没有」
和「五段齐全还是缺哪几段」。

**脚底那一条尤其只有它验得了** —— 锚点错一格的表现是这个人和别人的
前后关系错一档（y 排序按脚底排），而所有坐标看起来都完全正确。
调出辅助线，看橙色画布框的下沿是不是正好压在青色十字上。

## 9. 子弹与命中特效（M8-a）

**一份资源管两样**：`data/shots/<键>.tres`（[`PBShotSkin`](../src/view/shot_skin.gd)）
里既有「飞行中长什么样」也有「打中那一下炸开长什么样」。
分成两份的话，「配了子弹忘了配特效」的表现是**打中之后屏幕上什么都不发生**，
而它不报错 —— 而且两者本来就是一套美术。

| 字段 | 填什么 |
|---|---|
| `key` | 查它用的键。空着就用文件名 |
| `frames` | 一份 `SpriteFrames`，至少两段 |
| `anim_fly` | 飞行段，**循环**。默认名 `fly` |
| `anim_hit` | 命中段，**播一遍就收**。默认名 `hit`。火花活多久由这一段自己的帧率与帧数决定 |
| `spin` | 飞行中要不要转向飞行方向。有方向的东西（苦无、箭）要，圆球状的不要 —— 对称的球每帧转一个角度，边缘会抖 |
| `pixel_scale` / `smooth` | 规矩同战场形象（像素档整数倍，高清档填 `1/N` 并开 mipmap） |
| `tint_by_side` | 按**敌我**上色。白模是 `true`，真素材填 `false` |
| `additive_fly` / `additive_hit` | 两段各自用不用**加法混合**。黑底出图的发光类为真，洋红底的实体为假 |

**画布**：以**中心**为锚（不是脚底 —— 子弹不站在地上）。飞行段和命中段
共用同一个原点，所以命中段的画布要比子弹本身大一圈，火花才扩得开。
**源图一律朝右**，`spin` 会把它转向飞行方向。

**接上去**：普攻子弹配在名册 `data/roster.tsv` 的「普攻子弹」列（编辑器底栏「战场特效」面板一个按钮），
技能子弹配在技能上（`PBSkill.shot_key`）。**逐个配，不按属性推，也不挂在形象上** ——
同是火系一个吐火球一个扔苦无，同一张形象也能换一颗子弹。
出图、切图、生成资源的完整规格见 [素材规格_特效.md](素材规格_特效.md)。

**出手点与命中点**在战场形象那一侧配（`PBActorSkin` 的
`muzzle_offset` / `hit_offset`，像素、相对脚底、**向上为负 y**、未乘缩放）。
留空按身高派生（枪口约六成身高、命中点半身高）。**x 会跟着朝向自动翻转**，
所以填正数就是「身前」。这两个数**只在渲染层生效** ——
sim 是一个平面，没有高度轴，而进 sim 会改飞行距离进而改配平。

**空着照样跑**：`data/shots/` 目录不存在不是错，退回
[`PBWhiteModel.shot()`](../src/view/white_model.gd)（3 像素的方块 + 一圈四帧的
菱形火花），和白模那条理由逐字相同。

## 附：现在顶着的白模长什么样

[`PBWhiteModel`](../src/view/white_model.gd) 用代码画：忍者是方头方脑的人形
（头 + 身 + 两条腿 + 一条会伸出去的手臂），小怪是每系一个边数的多边形。
两边都只画纯白 + 底部一道暗边 + 一圈描边，颜色交给代码染。

它按的就是上面这份规格 —— **所以它同时是第一个「换皮」的样本**：
真素材进来时换掉的只是 `data/actors/*.tres`，渲染层一行不动。
