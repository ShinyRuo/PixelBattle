# AI 出图：一个忍者的整套战场形象

配套读 [`素材规格_战场形象.md`](素材规格_战场形象.md)（尺寸、锚点、朝向那一页）。
这一页只管**怎么让 AI 把图生出来，以及生出来之后怎么装进游戏**。

---

## 0. 先接受一件事：通用 AI 生不出可用的序列帧

这不是提示词写得不够好的问题，是这类模型的结构决定的：

- **帧间不连续。** 让它一次出 4 帧跑步图，四张里的人衣服、发型、比例都会变。
- **像素栅格是假的。** 它画的是「看起来像素风的插画」，放大看格子宽窄不一、
  边缘带半透明——而这个游戏的画布只有 54 见方，一格都错不起。
- **不认锚点。** 你说「脚踩在画布底边」它不懂，那是排版约束不是画面内容。

所以**可行的流程是「高清出图 → 人工降采样对齐」**，AI 负责的是造型和配色，
不是最终像素。下面这套提示词就是按这个前提写的：**一次只出一张、
高分辨率、纯色背景、正侧面站姿**，姿势之间靠**同一张参考图**保持一致。

> 想省这一步的话，专门做像素序列帧的工具（PixelLab、Scenario 之类）
> 比通用模型靠谱得多 —— 它们是**按骨架推帧**而不是每帧重抽一次卡，
> 直接吐 `.png` 序列。但**产出照样要过第 3 节的那道降采样与对齐** ——
> 脚底锚点错一格，游戏里前后关系就错一档。

**三条路，选一条**：

|   | 用什么                             | 产出                   | 看哪一节              |
| - | ---------------------------------- | ---------------------- | --------------------- |
| A | 文生图 + img2img                   | 每个姿势一张高清图     | §1 → §2            |
| B | 视频模型（Seedance / 可灵 / 即梦） | 一段连贯动作，人工转描 | §1 →**§2.5** |
| C | 像素序列帧工具（PixelLab）         | 直接是`.png` 序列    | §3 起                |

**三条路都要先出第 1 节那张立绘**，它是角色的基准。三条路也都要过第 3 节 ——
锚点和降采样是这个游戏的约束，不是某个工具的约束。

> **C 那条路要注意画布尺寸。** 这类工具的原生尺寸是 16/32/48/64，
> 而这里要的是**角色 41 像素高**：选 48（角色约 40~44 高，手修一两像素就行），
> **不要选 64 再缩到 41** —— 非整数比会把像素栅格压成宽窄不一的格子，
> 而它不报错，只表现为「看着有点脏」。
>
> 画布不是 54 没关系：`54` 只是 [PBWhiteModel] 自己的数字，
> 真素材这条路上 [method PBActorSkin.canvas_size] 是从 `SpriteFrames` 读的
> （`make_actor.ps1` 生成的阿斯玛就是 64×48），
> 换个尺寸要改的只有 `.tres` 里 [member PBActorSkin.height_px] 那一个数，
> `src/` 一行不动。

## 1. 主提示词（先出这一张，它是全套的基准）

把 `<ROLE>` 换成这个角色的设定，别的一个字不动。

**英文版喂 SD / Flux / Midjourney 那一路，中文版喂即梦、可灵、通义万相、
Liblib 上的国风模型那一路。** 不要把中文直接丢进 SD ——
那一路的文本编码器（CLIP / T5）对中文基本没有响应，
表现是「图出来了、但和你写的没关系」，而它不报错。

### 1.1 英文版

```
2D game character sprite, single character, full body, strict side view
(profile), facing right, standing idle pose, feet flat on an implied
ground line at the very bottom of the frame, arms relaxed at the sides.

<ROLE>

Art style: retro pixel art, 16-bit fighting game sprite, in the style of
Flash-era anime fighting games; bold clean 1px dark outline around the
whole silhouette; flat cel shading with at most 3 tones per material;
saturated but not neon palette; strong readable silhouette that stays
legible when shrunk to 41 pixels tall.

Composition: character centred horizontally, occupying the full height
of the frame with a small margin at the top, nothing cropped.
Plain flat magenta background (#FF00FF), no ground shadow, no scenery,
no text, no logo, no border, no frame, no character sheet, no multiple
poses, no turnaround.
```

### 1.2 中文版

把 `<角色>` 换成这个角色的设定，别的一个字不动。

```
2D 游戏角色像素立绘，单个角色，全身，严格正侧面视角（侧视图），面朝右，
站立待机姿势，双脚平踩在画面最底部的地平线上，双臂自然垂在身侧。

<角色>

画风：复古像素画，16 位机格斗游戏的角色图，Flash 时代日式格斗游戏的味道；
整个剪影外围一圈干净利落的 1 像素深色描边；平涂赛璐璐上色，
每种材质最多 3 个色阶；配色饱和但不刺眼；剪影结实，
缩到 40 像素高的时候仍然认得出是谁。

构图：角色水平居中，占满画面高度、顶部留一点余量，身体没有任何一处被裁掉。
背景是纯洋红色（#FF00FF）平涂。画面里只有这一个角色、只有这一个姿势，
地面干净没有影子，四周只有背景色。
```

> **最后那一段是故意写成肯定句的。** 中文那一路的模型有一批没有独立的
> 负面提示词框，而把「不要三视图」「不要影子」写进正面提示词经常适得其反 ——
> 模型看见的是「三视图」「影子」这几个词本身。所以中文版把英文版里
> 那串 `no ...` 全部翻成了「只有 …」；负面词只在**有独立输入框**时才填。

`<ROLE>` / `<角色>` 的写法（一句到两句，说清**剪影**和**配色**，
**不要写角色姓名**）：

> 英文例：`A young male ninja, spiky blonde hair, orange and black jumpsuit, blue forehead protector, red spiral emblem on the back.`
>
> 中文例：`一名年轻男忍者，金色刺猬头，橙黑相间的连体服，蓝色护额， 背后有红色漩涡纹章。`

**中文版尤其不能写角色姓名。** 国内模型的训练集里那几个名字对应着极强的
先验，写上去它会照着自己认识的那个 IP 画 —— 一是版权，二是画风当场跑偏成
番剧插画，而你要的是 16 位机的像素剪影。**这和铁律 5（代码里不出现角色名
字符串）是同一件事在美术那一侧的样子**：角色是一个 `id` 加一串外观描述，
不是一个名字。

**为什么这么写**

| 这一句                                                                  | 挡的是什么                                                           |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 严格正侧面、面朝右`strict side view (profile), facing right`          | 默认给你四分之三侧，那种图翻转之后会明显不对称                       |
| 双脚踩在画面最底部`feet flat ... at the very bottom of the frame`     | 脚底锚点唯一能在生成阶段争取到的东西                                 |
| 1 像素深色描边`1px dark outline`                                      | 战场上同一列会叠着七八个人，**没有描边就数不出几个人**（实测） |
| 每种材质最多 3 个色阶`at most 3 tones per material`                   | 降到 40 来个像素之后，渐变会糊成噪点                                 |
| 纯洋红背景`plain flat magenta background`                             | 抠背景最省事的颜色，人身上几乎不会出现                               |
| 只有这一个角色、只有这一个姿势`no character sheet, no multiple poses` | 不写它，十次有六次给你一张四宫格                                     |

## 2. 其余姿势：每一张都带上第 1 张当参考

**关键是「参考」而不是「重写描述」。** 用 img2img / reference image /
character reference 之类的功能，把第 1 张待机图喂进去，权重给中高
（img2img 的 denoise 建议 0.45~0.6：低了不改姿势，高了换个人）。
提示词只改**姿势那一句**，风格段和背景段一个字不动。

> 中文那一路的叫法不一样，找的是同一个东西：**「垫图」「参考图」
> 「角色一致性」「图生图」**。那个强度滑条（有的叫「参考强度」、
> 有的叫「变化幅度」）方向可能是反的 —— 先出两张试出哪一头是「更像原图」，
> 别照着 0.5 这个数字硬填。

| 段               | 换掉的那一句（英 / 中）                                                                                                                                                                    | 要几张 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| `idle`         | `standing idle pose, arms relaxed at the sides, slight breathing motion`站立待机姿势，双臂自然垂在身侧，呼吸般的轻微起伏                                                                 | 2~4    |
| `run`          | `running to the right, mid-stride, one leg forward one leg back, arms swinging, torso leaning slightly forward`向右奔跑，跑到一半，一条腿在前一条腿在后，双臂摆动，上身略微前倾          | 4~6    |
| `attack`       | `attacking to the right, arm fully extended forward in a strike, weight on the front foot, body twisted into the blow`向右出招，手臂完全向前伸直击出，重心压在前脚上，身体拧向出击的方向 | 3~5    |
| `cast`（可选） | `channelling chakra, both hands together in a hand seal in front of the chest, feet planted, energy glow around the hands` 凝聚查克拉，双手在胸前结印，双脚站定，手上有能量辉光          | 2~3    |
| `dead`（可选） | `lying face down on the ground, collapsed, seen from the side`面朝下倒在地上，整个人瘫倒，侧面视角                                                                                       | 1      |

**同一段里的几帧靠「插值」而不是「再生一次」**：出这一段的**首帧和末帧**，
中间帧在像素编辑器里手挪（一格一格地推手臂和腿），比再抽一次卡稳得多。
`run` 那种循环段，第 3 帧通常就是第 1 帧的镜像姿势。

**一次要出五段 × 一个角色 × 30 个角色，别手点。** 写个批处理脚本按上面的
表格套模板，一次跑完再统一挑。

## 2.5 另一条路：视频模型转描（Seedance / 可灵 / 即梦这一路）

手上只有视频模型的时候走这条。它和上面那条不是二选一 —— **第 1 节那张立绘
照样要先出**，这里只是把「其余姿势」换了个来源。

### 2.5.1 它给你的是动作，不是像素

视频模型输出的每一帧都是重新渲染的，所谓的像素栅格是幻觉：放大看格子宽窄不一、
边缘全是半透明，而且**逐帧还会抖**。指望抽出来直接用是不行的。

但它有一样文生图给不了的东西：**同一条视频里的帧之间是时间连贯的**，
那个人从头到尾是同一个人。所以分工是：

- **立绘**提供**像素** —— 最终成品里每一个色块都来自它
- **视频**提供**姿势** —— 告诉你第 3 帧的手臂抬到哪、腿分多开

在 Aseprite 里把视频帧铺一层当底稿（压低不透明度），照着它挪立绘的像素。
这叫**转描**，是 90 年代那批 2D 格斗游戏的真实做法。

> **所以提示词里不要写「像素风」。** 写了它会给你一段像素在抖的视频，
> 抽出来是噪点。要的是**厚描边、平涂、无渐变**的动画赛璐璐 ——
> 那种画面降采样之后色块是干净的。这一条和第 1 节正好相反，因为用途不同：
> 那边的产出是**成品**，这边的产出是**底稿**。

### 2.5.2 抽帧（ffmpeg）

```powershell
winget install Gyan.FFmpeg
```

装完**新开一个终端**才认得到 `ffmpeg`。

先出一张**联络表**（整段的缩略图拼成一张），用它挑帧号，别一帧帧翻：

```powershell
ffmpeg -i build\video\run.mp4 `
    -vf "fps=12,scale=160:-1,tile=8x5" build\run_sheet.png
```

挑好之后抽帧：

```powershell
New-Item -ItemType Directory -Force build\frames\run
ffmpeg -i build\video\run.mp4 -fps_mode passthrough build\frames\run\%03d.png
```

`-fps_mode passthrough`（老版本叫 `-vsync 0`）的意思是**一帧不丢也不补**。
不写它 ffmpeg 会按目标帧率重采样，你在联络表上挑好的帧号当场对不上，
**而它不报错** —— 抽出来的图看着都很正常。

只要中间一小段：

```powershell
ffmpeg -ss 00:00:01.4 -to 00:00:02.2 -i build\video\run.mp4 `
    -fps_mode passthrough build\frames\run\%03d.png
```

**缩放和对齐不要交给 ffmpeg**，仍然走下面第 3 节那三步手做 ——
ffmpeg 在这条链上只负责「抽帧」这一件事。

### 2.5.3 每段挑哪几帧

| 段         | 挑法                                                      | 帧数 |
| ---------- | --------------------------------------------------------- | ---- |
| `idle`   | 呼吸的**最高点**和**最低点**各一帧            | 2    |
| `run`    | 一只脚落地那一帧当起点，隔约四分之一个循环取一帧          | 4    |
| `attack` | **手臂伸到最长那一帧当 frame 0**，往后取 1~2 帧收招 | 3    |
| `cast`   | 起手一帧、结印完成一帧                                    | 2    |
| `dead`   | 趴稳之后任意一帧                                          | 1    |

`attack` 那条是硬要求（规格那页的自查清单里也有）：**第一帧就是打出去的那一下**。
起手动作占了前两帧的话，游戏里的伤害结算比画面早半拍，
玩家看到的是「先掉血、后挥手」。

`run` 的第 3 帧通常就是第 1 帧的镜像姿势，挑不到干净的可以直接翻转第 1 帧凑。

### 2.5.4 提示词：公共约束段

**每段一条视频，一次只生成一个动作**，别让它出合集。
**首帧图统一喂第 1 节那张立绘** —— 角色一致性全靠这个，不靠文字。

下面这段每一条都原样带上，只换最后那一句：

```
【固定机位】镜头完全不动，不推、不拉、不摇、不移，没有景深变化，没有运镜。

【角色】保持首帧那个人不变：发型、五官、服装款式、配色、身体比例全程不变。
严格正侧面、面朝右，始终停在画面正中，不转身、不离开画面。

【画风】保持首帧的样子：厚重的深色描边，平涂色块，每种材质最多 3 个色阶，
没有渐变、没有柔光、没有景深虚化。

【背景】纯洋红色平涂，全程保持干净：没有地面、没有影子、没有粒子、
没有烟尘、没有风、没有光效、没有文字。

【动作】<换这一句>
```

### 2.5.5 提示词：五个动作句

**`idle` 待机**

```
角色原地站立待机，动作幅度极小：只有呼吸带来的起伏，胸口和肩膀缓慢上下，
头几乎不动，双臂自然垂在身侧轻微晃动。双脚完全不动，脚底始终踩在同一条线上。
节奏缓慢、循环，全程不走动、不转身、不出招。
```

**`run` 奔跑**

```
角色原地奔跑，像在跑步机上一样，人始终停在画面正中不往前走。
双腿快速交替，一条腿在前一条腿在后，膝盖抬高；双臂前后大幅摆动；
上身略微前倾。完整跑满至少三个循环，速度均匀。
脚底始终落在同一条水平线上。
```

**`attack` 攻击**

```
角色向右出招三次，中间回到站立。每一次：起手极短，
手臂猛地向前伸直击出，重心压到前脚，身体拧向出击的方向，
在手臂伸到最长的那一瞬间明显停顿一下，然后收招回到站立。
双脚位置基本不动，人不往前冲。
```

**`cast` 结印**

```
角色双手在胸前合拢结印，双脚站定不动，身体微微下沉蓄力，
手上出现淡淡的能量辉光。动作缓慢，结印完成后保持不动两秒。
全程不走动、不转身。
```

**`dead` 倒地**

```
角色被击中，向后踉跄半步，然后向前扑倒，面朝下趴在地上。
倒地之后完全静止两秒。整个过程一次完成，镜头不动。
```

### 2.5.6 三句不能删的，各挡一种静默失败

| 那一句                             | 不写会怎样                                                                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 「原地奔跑，像在跑步机上」         | 人会跑出画。跑出画之后每一帧的脚底位置都不同，而脚底是整套素材唯一的锚点（[member PBActorSkin.foot_offset]），对不齐的表现是游戏里这个人在原地抖 |
| 「伸到最长的那一瞬间明显停顿一下」 | 模型默认把动作做得很顺滑，而顺滑意味着**没有一帧是清晰的最大伸展** —— 那一帧正是 `attack` 的 frame 0                                   |
| 「背景全程保持干净」               | 它极爱加烟尘和风。糊在角色边上的粒子在抠背景那一步会连着人一起被选中，留下一圈缺口                                                               |

参数：**分辨率拉满、时长 5 秒、同一条提示词多生几条挑**。
5 秒 24fps 是 120 帧，而你一共只要 12 帧 —— 抽帧那一步一点都不缺素材。

## 3. 出图之后：三步降采样对齐（这一步不能跳）

工具用 Aseprite（最顺手）、或者 Photoshop / GIMP / libresprite 都行。

1. **抠背景。** 按洋红色选中，删掉。**边缘不要羽化** ——
   留下的半透明像素在游戏里会变成一圈脏边。
2. **降到 41 像素高。** 缩放算法必须选**最近邻 / Nearest Neighbor**
   （Aseprite 里是 `Sprite > Sprite Size > Nearest`）。
   双线性会把每个像素糊成四个半调像素，像素风当场消失。
   降完**一定要手工修一遍**：眼睛、发梢、武器这些一两像素的东西
   降采样之后必然糊掉，得手动点回来。
3. **对齐画布。** 新建 54×54 画布（宽不够就加宽），把人贴进去，
   **脚底落在最底一行、水平居中**。
   同一个角色的**所有帧共用这一个对齐**——逐帧各对各的，人会在动画里抖。

自查（和规格那页的清单是同一份）：

- [ ] 同一个角色的每一帧尺寸完全一致（make_actor.ps1 生成的是 64×48）
- [ ] 脚踩在最底一行，水平居中

## 4. 装进游戏：一条命令

**第 3 节那三步（抠背景、降采样、对齐）加上建 `SpriteFrames`，全部自动了**
（M6-f）。视频那条路上不用开 Aseprite，也不用开 Godot 编辑器：

```powershell
.\scripts\make_actor.ps1 -Key asm
```

它要的输入是 `aires\<Key>_<段名>.mp4` 四段（`idle` / `run` / `attack` / `dead`），
每段一条视频，按第 2.5 节那套提示词生成、洋红背景。跑完得到：

```
assets\actors\asm\*.png            10 张成品帧
data\actors\frames\asm.tres        图集（SpriteFrames）
data\actors\asm.tres               形象表（PBActorSkin）
```

**最后只剩一步是手做的**：把 `data\characters\<角色>.tres` 的
`actor_key` 填成 `asm`（那是个纯文本文件，加一行就行）。然后开预览台看（§4.6）。

### 4.0 它替你做了什么

| 手做的那一步 | 自动版怎么做的 |
|---|---|
| 抠洋红背景 | ffmpeg `colorkey` |
| 降采样不糊 | **预乘 alpha** 再按面积平均 —— 见下面那条 |
| 对齐画布 | 量出**脚底那一截的中点**，坐到画布底边中点上 |
| 挑帧 | 量出来的：跑动做剪影自相关找循环、攻击取手伸得最远那一帧 |
| 定画布尺寸 | 按挑中的那几帧算，装得下出拳的伸展 |
| 加 1px 描边 | 把剪影最外圈压暗（**不往外扩**，扩了身高就超了） |
| 建 `SpriteFrames` | 脚本写 `.tres`，帧率与循环按段设好 |

> **「预乘」那一条是这条链上最容易错的地方。** 抠完背景之后背景像素虽然
> 全透明了，它的 RGB 仍然是洋红 —— 缩放会把相邻像素平均起来，
> 于是人物边缘渗出一圈粉色，**而 alpha 看起来完全正常**。
> 先把透明像素的 RGB 归零（`rgb *= a`）再缩，缩完除回来。

> **挑帧不靠数格子。** `attack` 的第一帧必须是打出去的那一下（规格第 8 节），
> 靠肉眼在联络表上数十次有三次差一帧，而差一帧的表现是
> 「先掉血、后挥手」。脚本量的是「从脚底中点往右到剪影右沿有多远」，
> 取最大的那一帧。跑动同理：循环长度靠剪影自相关量，数错一帧就一瘸一拐。

### 4.0.1 常用开关

| 开关 | 干什么 |
|---|---|
| `-SkipExtract` | 视频没变、只改了切图参数时跳过 ffmpeg 那一趟（快很多） |
| `-Anims idle,run,attack` | 只有三段视频时用（`dead` 缺了会退回待机段） |
| `-SrcDir <目录>` | 视频不在 `aires\` 时 |
| `-Preview` | 跑完直接开预览台 |

### 4.0.2 手做那条路（下面 4.1~4.5）什么时候还需要

第 0 节的 A / C 两条路线（文生图、PixelLab）产出的是**散帧**不是视频，
`make_actor.ps1` 现在只吃视频。那两条路仍然照 4.1~4.5 手做，
或者先把帧拼成一段视频再喂给它。

假设角色叫 `naruto`（`actor_key`，小写英文 + 下划线，**不要用中文名**）。

### 4.1 放文件

把切好的帧放进 `assets/actors/naruto/`：

```
assets/actors/naruto/idle_0.png  idle_1.png
assets/actors/naruto/run_0.png   run_1.png  run_2.png  run_3.png
assets/actors/naruto/attack_0.png  attack_1.png  attack_2.png
```

放完在 Godot 编辑器里等它导入完（或者跑一次 `.\scripts\check.ps1`，
第 1 步就是 `--import`）。

### 4.2 关掉纹理过滤（**漏了这一步整套图会糊**）

项目已经全局设成了「最近邻」（`project.godot` 的
`textures/canvas_textures/default_texture_filter=0`），所以正常不用管。
但如果某张图在编辑器里被单独改过导入设置，要在**导入面板**里把
`Filter` 关掉、`Mipmaps` 关掉，然后按「重新导入」。

### 4.3 建 `SpriteFrames`

1. 新建一个资源，类型选 `SpriteFrames`，存成
   **`data/actors/frames/naruto.tres`**（注意是 `frames/` 子目录 ——
   `PBActorLibrary` 把 `data/actors/` 下的每个 `.tres` 都当成一张
   `PBActorSkin`，图集放它旁边的话每次读表都刷一条错误，而游戏照跑）
2. 双击打开，底部的动画面板里建三段：`idle` / `run` / `attack`
   （**名字必须是这三个**，或者在下一步的 `.tres` 里改映射）
3. 每一段把对应的 png 按顺序拖进去
4. 每一段设帧率：`idle` 4~6、`run` 10~12、`attack` 12~16
5. 循环：`idle` 和 `run` 开，**`attack` 关**
6. 把默认那个空的 `default` 段删掉

### 4.4 建 `PBActorSkin`

新建资源，类型选 `PBActorSkin`，存成 `data/actors/naruto.tres`，填：

| 字段                                           | 填什么                                                               |
| ---------------------------------------------- | -------------------------------------------------------------------- |
| `key`                                        | `naruto`（和文件名一样；留空会按文件名兜底）                       |
| `frames`                                     | 拖`frames/naruto.tres` 进来                                        |
| `anim_idle` / `anim_run` / `anim_attack` | `idle` / `run` / `attack`                                      |
| `anim_cast` / `anim_dead`                  | 有就填，没有留着——查不到会自动退回攻击段和待机段                   |
| `skill_anims`                                | `{ 忍术 id: 段名 }`，没有就空着                                    |
| `source_faces`                               | 你画的是朝右就`RIGHT`，朝左就 `LEFT`                             |
| `pixel_scale`                                | `1.0`。**要放大只能填整数**，非整数会切碎像素栅格            |
| `foot_offset`                                | **留 `(0,0)`**，那表示「画布底边中点」，也就是规格里的默认锚 |
| `tint_by_element`                            | **`false`**（真素材自己有颜色，再染一层会把美术定的色拉偏）  |
| `height_px`                                  | 站着时从脚底到头顶多少像素，36 画布的话一般填`27`                  |
