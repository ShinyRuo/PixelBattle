# AI 出图：一个忍者的整套战场形象

配套读 [`素材规格_战场形象.md`](素材规格_战场形象.md)（尺寸、锚点、朝向那一页）。
这一页只管**怎么让 AI 把图生出来，以及生出来之后怎么装进游戏**。

---

## 0. 先接受一件事：通用 AI 生不出可用的序列帧

这不是提示词写得不够好的问题，是这类模型的结构决定的：

- **帧间不连续。** 让它一次出 4 帧跑步图，四张里的人衣服、发型、比例都会变。
- **像素栅格是假的。** 它画的是「看起来像素风的插画」，放大看格子宽窄不一、
  边缘带半透明——而像素档那一路一格都错不起。
- **不认锚点。** 你说「脚踩在画布底边」它不懂，那是排版约束不是画面内容。

所以**可行的流程是「高清出图 → 人工降采样对齐」**，AI 负责的是造型和配色，
不是最终像素。下面这套提示词就是按这个前提写的：**一次只出一张、
高分辨率、纯色背景、正侧面站姿**，姿势之间靠**同一张参考图**保持一致。

> 想省这一步的话，专门做像素序列帧的工具（PixelLab、Scenario 之类）
> 比通用模型靠谱得多 —— 它们是**按骨架推帧**而不是每帧重抽一次卡，
> 直接吐 `.png` 序列。但**产出照样要过第 3 节的那道降采样与对齐** ——
> 脚底锚点错一格，游戏里前后关系就错一档。

> **D 那条路把上面第一条推翻了一半。** 「帧间不连续」说的是**一帧一张、
> 每张重抽一次卡**；而让模型在**同一张画布上一次画完六格**，它自己就会保持
> 角色一致 —— 实测衣服、配色、体型基本不跳。另外两条照旧成立（像素栅格
> 还是假的、还是不认锚点），所以那条路的产出**照样要过第 3 节**。见 §2.7。

**四条路，选一条**：

|   | 用什么                                       | 产出                                 | 看哪一节              |
| - | -------------------------------------------- | ------------------------------------ | --------------------- |
| A | 文生图 + img2img                             | 每个姿势一张高清图                   | §1 → §2            |
| B | 视频模型（Seedance / 可灵 / 即梦）           | 一段连贯动作，人工转描               | §1 →**§2.5** |
| C | 像素序列帧工具（PixelLab）                   | 直接是`.png` 序列                  | §3 起                |
| D | **图像模型出图集**（GPT Image 这一路） | **一段动作一张 2×3 六格图集** | §1 →**§2.7** |

**四条路都要先出第 1 节那张立绘**，它是角色的基准。四条路也都要过第 3 节 ——
锚点和降采样是这个游戏的约束，不是某个工具的约束。

> **C 那条路只出得了像素档，而且要注意画布尺寸。** 这类工具的原生尺寸是
> 16/32/48/64，而这里要的是**角色 60 像素高**：选 64（角色约 56~62 高，
> 手修一两像素就行），**不要选 48 再放大到 60** —— 非整数比会把像素栅格
> 压成宽窄不一的格子，而它不报错，只表现为「看着有点脏」。
>
> **现有三个真素材走的是 B 那条路的高清档**（贴图 180 高，见素材规格第 2 节）。
> C 出的图是硬边像素，混在里面会明显是另一路 —— 要么整个角色阵容统一，
> 要么就认下这个差别。
>
> 画布不是某个固定数没关系：[method PBActorSkin.canvas_size] 是从
> `SpriteFrames` 读的（现有三个真素材是 260×186 / 230×186 / 360×186），
> 换个尺寸要改的只有 `.tres` 里 [member PBActorSkin.height_px] 那一个数，
> `src/` 一行不动。

## 1. 主提示词（先出这一张，它是全套的基准）

把 `<ROLE>` 换成这个角色的设定，别的一个字不动。

**英文版喂 SD / Flux / Midjourney 那一路，中文版喂即梦、可灵、通义万相、
Liblib 上的国风模型那一路。** 不要把中文直接丢进 SD ——
那一路的文本编码器（CLIP / T5）对中文基本没有响应，
表现是「图出来了、但和你写的没关系」，而它不报错。

### 1.1 英文版

```
2D game character sprite, single character, full body, strict side view
(profile), facing right, standing idle pose, feet flat on an implied
ground line at the very bottom of the frame, arms relaxed at the sides.

<ROLE>

Art style: retro pixel art, 16-bit fighting game sprite, in the style of
Flash-era anime fighting games; bold clean 1px dark outline around the
whole silhouette; flat cel shading with at most 3 tones per material;
saturated but not neon palette; strong readable silhouette that stays
legible when shrunk to 60 pixels tall.

Composition: character centred horizontally, occupying the full height
of the frame with a small margin at the top, nothing cropped.
Plain flat magenta background (#FF00FF), no ground shadow, no scenery,
no text, no logo, no border, no frame, no character sheet, no multiple
poses, no turnaround.
```

### 1.2 中文版

把 `<角色>` 换成这个角色的设定，别的一个字不动。

```
2D 游戏角色像素立绘，单个角色，全身，严格正侧面视角（侧视图），面朝右，
站立待机姿势，双脚平踩在画面最底部的地平线上，双臂自然垂在身侧。

<角色>

画风：复古像素画，16 位机格斗游戏的角色图，Flash 时代日式格斗游戏的味道；
整个剪影外围一圈干净利落的 1 像素深色描边；平涂赛璐璐上色，
每种材质最多 3 个色阶；配色饱和但不刺眼；剪影结实，
缩到 60 像素高的时候仍然认得出是谁。

构图：角色水平居中，占满画面高度、顶部留一点余量，身体没有任何一处被裁掉。
背景是纯洋红色（#FF00FF）平涂。画面里只有这一个角色、只有这一个姿势，
地面干净没有影子，四周只有背景色。
```

> **最后那一段是故意写成肯定句的。** 中文那一路的模型有一批没有独立的
> 负面提示词框，而把「不要三视图」「不要影子」写进正面提示词经常适得其反 ——
> 模型看见的是「三视图」「影子」这几个词本身。所以中文版把英文版里
> 那串 `no ...` 全部翻成了「只有 …」；负面词只在**有独立输入框**时才填。

`<ROLE>` / `<角色>` 的写法（一句到两句，说清**剪影**和**配色**，
**不要写角色姓名**）：

> 英文例：`A young male ninja, spiky blonde hair, orange and black jumpsuit, blue forehead protector, red spiral emblem on the back.`
>
> 中文例：`一名年轻男忍者，金色刺猬头，橙黑相间的连体服，蓝色护额， 背后有红色漩涡纹章。`

**中文版尤其不能写角色姓名。** 国内模型的训练集里那几个名字对应着极强的
先验，写上去它会照着自己认识的那个 IP 画 —— 一是版权，二是画风当场跑偏成
番剧插画，而你要的是 16 位机的像素剪影。**这和铁律 5（代码里不出现角色名
字符串）是同一件事在美术那一侧的样子**：角色是一个 `id` 加一串外观描述，
不是一个名字。

**为什么这么写**

| 这一句                                                                  | 挡的是什么                                                           |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 严格正侧面、面朝右`strict side view (profile), facing right`          | 默认给你四分之三侧，那种图翻转之后会明显不对称                       |
| 双脚踩在画面最底部`feet flat ... at the very bottom of the frame`     | 脚底锚点唯一能在生成阶段争取到的东西                                 |
| 1 像素深色描边`1px dark outline`                                      | 战场上同一列会叠着七八个人，**没有描边就数不出几个人**（实测） |
| 每种材质最多 3 个色阶`at most 3 tones per material`                   | 像素档降到几十个像素之后渐变会糊成噪点（高清档不受这条限制）         |
| 纯洋红背景`plain flat magenta background`                             | 抠背景最省事的颜色，人身上几乎不会出现                               |
| 只有这一个角色、只有这一个姿势`no character sheet, no multiple poses` | 不写它，十次有六次给你一张四宫格                                     |

### 1.2.1 怎么写 `<角色>`：像但不是

这个游戏复刻的是《忍法战场》，角色**取自原作的气质、但不能是原作的那个人**。
上一节说了「不要写角色姓名」，这一节说不写名字之后那一格填什么。

**「像但不是」不能靠形容词求，只能靠替换项做。**
`一个很像鸣人但不完全一样的忍者` 这种写法是无效的 —— 模型只吃**画面里能画出来
的名词**，「不完全一样」画不出来。它的实际反应是**要么照着原作画，要么随机丢掉
一半特征**，两头都不受你控制，而且不报错。

所以那道减法要你自己先做完：把原角色拆成**剪影 / 符号 / 配色**三层，**留一层、换两层**。

| 层             | 是什么                               | 怎么处理                                | 为什么                                                   |
| -------------- | ------------------------------------ | --------------------------------------- | -------------------------------------------------------- |
| **剪影** | 发型轮廓、体型、披风或长袍、武器形状 | **保留**                          | 60 像素高的战场上玩家只认得出剪影，别的都是噪点          |
| **符号** | 护额上的村徽、背后的纹章、脸上的纹路 | **必换**                          | 版权最实的一层，也是模型先验最强的一层，写上去它整张照抄 |
| **配色** | 主色相                               | **移 30~60 度**，明度和饱和度不动 | 剪影不变，但「不是同一个人」                             |

替换项照这个方向自己列：

- 漩涡纹章 → 同位置的**原创几何纹**（三角环、断裂的圆、四瓣叶）
- 村徽护额 → **无纹的素金属护额**，或者自己编一道刻痕
- 脸上三道须痕 → **眼下一道疤** / 眼周刺青
- 特定瞳术 → **单色异瞳 + 环形虹膜**（不要写那个术的名字）
- 葫芦 → **背后的陶罐** / 缠布的圆筒

写出来是一到两句、**只有名词、不带任何比较级**：

> 中文例：`一名年轻男忍者，蓬乱的浅金色刺猬短发，琥珀色与炭黑拼接的连体服，素面金属护额，背后有一枚断裂圆环的深红纹章。`
>
> 英文例：`A lean teenage ninja, dark indigo swept-back hair, high-collared slate blue tunic, one bandaged forearm, a plain steel forehead plate, a broken-circle crest on the back.`

三条硬规矩：

1. **不写角色姓名**，也不写作品名、村名、术名这类**专有名词**。理由见上一节；
   对 Gemini（banana）这一路尤其要紧 —— 它的语言理解比 SD 那一路强得多，
   **认得出你在指谁**。
2. **不写「像 XX」「XX 风格的角色」** —— 那等于把名字换个说法写进去。
3. **加一句 `an original character design` / 「原创角色设计」** —— 这是模型
   听得懂的行为指令，会把结果往「同类型但不特指」推。

> **banana 这一路还有两点和上面的假设不同。**
>
> **参考图只喂风格板，不喂角色。** 它的强项是多图参考一致性，但参考图带过去的
> **不只是画风，还有脸**。30 个角色要统一画风，喂的是**第一个定稿角色**
> 加一句「保持这张的描边粗细、色阶数、比例，人物换成下面描述的这一个」，
> **不是原作截图** —— 喂截图就是直接抄，那是这道减法里最容易漏的口子。
>
> **它吃自然语言段落，不吃 tag 堆。** 上面两段提示词原样用，不要改写成逗号
> 分隔的关键词串。它也没有独立的负面提示词框，所以下一节那串**按 1.2 的规矩
> 翻成肯定句**写进正文。

## 2. 其余姿势：每一张都带上第 1 张当参考

**关键是「参考」而不是「重写描述」。** 用 img2img / reference image /
character reference 之类的功能，把第 1 张待机图喂进去，权重给中高
（img2img 的 denoise 建议 0.45~0.6：低了不改姿势，高了换个人）。
提示词只改**姿势那一句**，风格段和背景段一个字不动。

> 中文那一路的叫法不一样，找的是同一个东西：**「垫图」「参考图」
> 「角色一致性」「图生图」**。那个强度滑条（有的叫「参考强度」、
> 有的叫「变化幅度」）方向可能是反的 —— 先出两张试出哪一头是「更像原图」，
> 别照着 0.5 这个数字硬填。

| 段               | 换掉的那一句（英 / 中）                                                                                                                                                                    | 要几张 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| `idle`         | `standing idle pose, arms relaxed at the sides, slight breathing motion`站立待机姿势，双臂自然垂在身侧，呼吸般的轻微起伏                                                                 | 2~4    |
| `run`          | `running to the right, mid-stride, one leg forward one leg back, arms swinging, torso leaning slightly forward`向右奔跑，跑到一半，一条腿在前一条腿在后，双臂摆动，上身略微前倾          | 4~6    |
| `attack`       | `attacking to the right, arm fully extended forward in a strike, weight on the front foot, body twisted into the blow`向右出招，手臂完全向前伸直击出，重心压在前脚上，身体拧向出击的方向 | 3~5    |
| `cast`（可选） | `channelling chakra, both hands together in a hand seal in front of the chest, feet planted, energy glow around the hands` 凝聚查克拉，双手在胸前结印，双脚站定，手上有能量辉光          | 2~3    |
| `dead`（可选） | `lying face down on the ground, collapsed, seen from the side`面朝下倒在地上，整个人瘫倒，侧面视角                                                                                       | 1      |

**同一段里的几帧靠「插值」而不是「再生一次」**：出这一段的**首帧和末帧**，
中间帧在像素编辑器里手挪（一格一格地推手臂和腿），比再抽一次卡稳得多。
`run` 那种循环段，第 3 帧通常就是第 1 帧的镜像姿势。

**一次要出五段 × 一个角色 × 30 个角色，别手点。** 写个批处理脚本按上面的
表格套模板，一次跑完再统一挑。

## 2.5 另一条路：视频模型转描（Seedance / 可灵 / 即梦这一路）

手上只有视频模型的时候走这条。它和上面那条不是二选一 —— **第 1 节那张立绘
照样要先出**，这里只是把「其余姿势」换了个来源。

### 2.5.1 它给你的是动作，不是像素

视频模型输出的每一帧都是重新渲染的，所谓的像素栅格是幻觉：放大看格子宽窄不一、
边缘全是半透明，而且**逐帧还会抖**。指望抽出来直接用是不行的。

但它有一样文生图给不了的东西：**同一条视频里的帧之间是时间连贯的**，
那个人从头到尾是同一个人。所以分工是：

- **立绘**提供**像素** —— 最终成品里每一个色块都来自它
- **视频**提供**姿势** —— 告诉你第 3 帧的手臂抬到哪、腿分多开

在 Aseprite 里把视频帧铺一层当底稿（压低不透明度），照着它挪立绘的像素。
这叫**转描**，是 90 年代那批 2D 格斗游戏的真实做法。

> **所以提示词里不要写「像素风」。** 写了它会给你一段像素在抖的视频，
> 抽出来是噪点。要的是**厚描边、平涂、无渐变**的动画赛璐璐 ——
> 那种画面降采样之后色块是干净的。这一条和第 1 节正好相反，因为用途不同：
> 那边的产出是**成品**，这边的产出是**底稿**。

### 2.5.2 抽帧（ffmpeg）

```powershell
winget install Gyan.FFmpeg
```

装完**新开一个终端**才认得到 `ffmpeg`。

先出一张**联络表**（整段的缩略图拼成一张），用它挑帧号，别一帧帧翻：

```powershell
ffmpeg -i build\video\run.mp4 `
    -vf "fps=12,scale=160:-1,tile=8x5" build\run_sheet.png
```

挑好之后抽帧：

```powershell
New-Item -ItemType Directory -Force build\frames\run
ffmpeg -i build\video\run.mp4 -fps_mode passthrough build\frames\run\%03d.png
```

`-fps_mode passthrough`（老版本叫 `-vsync 0`）的意思是**一帧不丢也不补**。
不写它 ffmpeg 会按目标帧率重采样，你在联络表上挑好的帧号当场对不上，
**而它不报错** —— 抽出来的图看着都很正常。

只要中间一小段：

```powershell
ffmpeg -ss 00:00:01.4 -to 00:00:02.2 -i build\video\run.mp4 `
    -fps_mode passthrough build\frames\run\%03d.png
```

**缩放和对齐不要交给 ffmpeg**，仍然走下面第 3 节那三步手做 ——
ffmpeg 在这条链上只负责「抽帧」这一件事。

### 2.5.3 每段挑哪几帧

| 段         | 挑法                                                      | 帧数 |
| ---------- | --------------------------------------------------------- | ---- |
| `idle`   | 呼吸的**最高点**和**最低点**各一帧            | 2    |
| `run`    | 一只脚落地那一帧当起点，隔约四分之一个循环取一帧          | 4    |
| `attack` | **手臂伸到最长那一帧当 frame 0**，往后取 1~2 帧收招 | 3    |
| `cast`   | 起手一帧、结印完成一帧                                    | 2    |
| `dead`   | 趴稳之后任意一帧                                          | 1    |

`attack` 那条是硬要求（规格那页的自查清单里也有）：**第一帧就是打出去的那一下**。
起手动作占了前两帧的话，游戏里的伤害结算比画面早半拍，
玩家看到的是「先掉血、后挥手」。

`run` 的第 3 帧通常就是第 1 帧的镜像姿势，挑不到干净的可以直接翻转第 1 帧凑。

### 2.5.4 提示词：公共约束段

**每段一条视频，一次只生成一个动作**，别让它出合集。
**首帧图统一喂第 1 节那张立绘** —— 角色一致性全靠这个，不靠文字。

下面这段每一条都原样带上，只换最后那一句：

```
【固定机位】镜头完全不动，不推、不拉、不摇、不移，没有景深变化，没有运镜。

【角色】保持首帧那个人不变：发型、五官、服装款式、配色、身体比例全程不变。
严格正侧面、面朝右，始终停在画面正中，不转身、不离开画面，画面包含整个身体。

【画风】保持首帧的样子：厚重的深色描边，平涂色块，每种材质最多 3 个色阶，
没有渐变、没有柔光、没有景深虚化。

【背景】纯洋红色平涂，全程保持干净：没有地面、没有影子、没有粒子、
没有烟尘、没有风、没有光效、没有文字。

【动作】<换这一句>
```

### 2.5.5 提示词：五个动作句

**`idle` 待机**

```
角色原地站立待机，动作幅度极小：只有呼吸带来的起伏，胸口和肩膀缓慢上下，
头几乎不动，双臂自然垂在身侧轻微晃动。双脚完全不动，脚底始终踩在同一条线上。
节奏缓慢、循环，全程不走动、不转身、不出招。
```

**`run` 奔跑**

```
身体大幅前倾，上半身压低，双臂向后伸直甩开，不向前摆臂。腿部大步快速蹬跑，膝盖抬高，身体重心靠前，躯干几乎与地面形成一定夹角。
脚底始终落在同一条水平线上。
```

**`attack` 攻击	**

```
角色向右出招三次，中间回到站立。每一次：起手极短，
手臂猛地向前伸直击出，重心压到前脚，身体拧向出击的方向，
在手臂伸到最长的那一瞬间明显停顿一下，然后收招回到站立。
双脚位置基本不动，人不往前冲。
```

**`cast` 结印**

```
角色双手在胸前合拢结印，双脚站定不动，身体微微下沉蓄力，
手上出现淡淡的能量辉光。动作缓慢，结印完成后保持不动两秒。
全程不走动、不转身。
```

**`dead` 倒地**

```
角色向后踉跄半步，然后向前扑倒，面朝下趴在地上。
倒地之后完全静止两秒。整个过程一次完成，镜头不动。
```

### 2.5.6 三句不能删的，各挡一种静默失败

| 那一句                             | 不写会怎样                                                                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 「原地奔跑，像在跑步机上」         | 人会跑出画。跑出画之后每一帧的脚底位置都不同，而脚底是整套素材唯一的锚点（[member PBActorSkin.foot_offset]），对不齐的表现是游戏里这个人在原地抖 |
| 「伸到最长的那一瞬间明显停顿一下」 | 模型默认把动作做得很顺滑，而顺滑意味着**没有一帧是清晰的最大伸展** —— 那一帧正是 `attack` 的 frame 0                                   |
| 「背景全程保持干净」               | 它极爱加烟尘和风。糊在角色边上的粒子在抠背景那一步会连着人一起被选中，留下一圈缺口                                                               |

参数：**分辨率拉满、时长 5 秒、同一条提示词多生几条挑**。
5 秒 24fps 是 120 帧，而你一共只要 12 帧 —— 抽帧那一步一点都不缺素材。

## 2.6 首帧图先降一道：编辑器里那块「降采样」面板

文生图那一路出的立绘是**看起来像素风的插画**：边缘带半透明、格子宽窄不一、
脸画得清清楚楚（§0 第二条）。直接拿它当首帧图有两个后果 ——
视频模型会照着那些细节继续画，而**它先要过一遍版权审核**，
而脸正是过不去的那一样。

M6-p 起有一块面板把它**真的**降到几十像素高，再最近邻放大回去：
每一格都是实心方块，脸上只剩几个像素点。

编辑器底栏点 **「降采样」**：① 选图 → ② 出六档预览 → ③ 挑一档存盘。

**六档并排是这块面板存在的全部理由。** 「降到多少像素高」光看数字选不出来 ——
48 只剩色块、96 能看出发型和衣服的分界、128 还能看出一点脸，
而每个角色的临界点都不一样（深色衣服比浅色耐压，长发比短发耐压）。
命令行那条路要试六次，每次都得开图看。

批量走 30 个角色仍然用命令行（没人想点 180 次按钮）：

```powershell
.\scripts\pixelate.ps1 -In aires\raw -Height 96
```

| 开关        | 干什么                                  |
| ----------- | --------------------------------------- |
| `-Height` | 降到多少像素高，默认 96                 |
| `-Colors` | 调色板压到几种颜色，默认 24，`0` 关掉 |
| `-Tol`    | 抠洋红的容差，默认 0.20                 |
| `-NoKey`  | 背景不是洋红时用                        |

**流水线只有一份**（[`PBPixelate`](../src/tools/pixelate.gd)），面板和命令行都只是
它的调用方 —— 和 [`PBActorForge`](../src/tools/actor_forge.gd) 同一条规矩：
各写一份的话「命令行出的图和插件出的图差一个色阶」迟早发生，而它不报错，
表现是同一个角色的四段视频首帧不是同一张图，**而角色一致性全押在那张图上**。

四条不肯让步的：

- **抠洋红要连预乘一起做。** 抠完之后透明像素的 RGB 仍然是洋红，缩放一平均
  就往人物边缘渗粉，**而 alpha 看起来完全正常**（和 §4.0 那条是同一个坑）。
- **alpha 要二值化。** 降采样会产出一圈半透明边缘，盖回洋红上又是一圈粉边；
  砍成「要么在要么不在」，后面 `make_actor` 那一趟的抠色才干净。
- **放大只能最近邻。** 双线性会把刚做出来的方块又糊回去，
  而那时图看起来「还行」，只是白做了。
- **抠色容差默认 0.20，粉发的角色不要往上调。** 浅粉到洋红的距离只有 0.41，
  调到 `make_actor` 那边用的 0.34 就开始啃头发，而它不报错。
  那边面对的是视频帧（带压缩噪点）所以必须松，这边是干净的 PNG。

**压调色板（`-Colors`）不是防错的，是效果**：渐变和高光被并成一块，
「插画感」掉得比降分辨率还快。它走的是中位切分，**背景那个洋红一定占一个色位**
（面积最大的一块），所以压完之后 `make_actor` 仍然抠得到它。

## 2.7 第四条路：一张图集出一整段（GPT Image 这一路）

**这条路把第 0 节那个前提推翻了一半。** 「帧间不连续」是针对
**一帧一张、每张重抽一次卡**说的 —— 而这一路是让模型在**同一张画布上
一次画完六格**，一致性是它自己在一次生成里保住的，不用靠参考图去追。

没被推翻的那两条照旧：**像素栅格是假的**（还要过第 3 节的降采样）、
**不认锚点**（脚底对齐仍然由 [PBActorForge] 做）。所以这一路省掉的是
「逐张追一致性」，不是「对齐」。

### 2.7.1 形状：四段各一张图集，每张 2×3 六格

|            | 管线要几帧 | 六格给你的                   | 挑帧靠什么                             |
| ---------- | ---------- | ---------------------------- | -------------------------------------- |
| `idle`   | 2          | 余量                         | 起伏最高/最低那两格（`breath`）      |
| `run`    | 4          | **正好一个完整循环**   | 剪影自相关找周期（`cycle`）          |
| `attack` | 3          | **正好一次出手的分解** | 手伸得最远那一格当第 0 帧（`reach`） |
| `dead`   | 1~3        | 倒地全过程                   | 最后那几格（`settle`）               |

**六格统一不是因为每段都要六帧**，是因为固定的 2×3 网格让切图这一步
（工具和人）都不用每次数格子。多出来的帧不浪费 —— 挑帧那一环
（§4.0.3 那块面板）本来就是「从多里挑少」。

> **`dead` 和 `idle` 要一起出、同一次会话。**
> [method PBActorForge.scales] 里 `dead` 段的缩放比是**借 `idle` 的** ——
> 人躺着，包围盒高度不是身高，照自己算的话他躺着也「站那么高」。
> 两张图不同批次、人物比例不一样的话，那个角色一倒下就会突然变大或变小，
> **而它不报错**。

把负面全部写成肯定句；英文版可以留 `no ...` 串，它的语言理解吃得住。

**中文版**：

### 2.7.3 四段各自的动作句（接在公共段后面）

**`idle`（待机）** —— 这一段最容易出错：不写死的话模型会给你六个不同姿势。

```
这六格是【待机】。角色站着不动，六格的姿势几乎完全一样 ——
脚的位置一格都不挪，重心不移，手臂保持同样的垂放姿势。
六格之间唯一的差别是呼吸带来的极轻微起伏：胸口和肩膀上下浮动一两个像素，
发梢和衣摆轻微飘动。第 1 格是呼气的最低点，第 3 格是吸气的最高点，
第 6 格回到接近第 1 格的位置，接得上、能循环。
```

**`run`（奔跑）**：

```
这六格是【奔跑】，六格构成一个完整的循环，第 6 格接回第 1 格是连续的。
六格依次是：
1 左脚触地承重，右腿在后
2 身体前移，右腿向前摆出
3 双脚离地的腾空，两腿交错
4 右脚触地承重，左腿在后
5 身体前移，左腿向前摆出
6 双脚离地的腾空，两腿交错
也就是两步走完一个循环。手臂前后自然摆动、和腿反相，身体略微前倾。
每一格里角色仍然停在这一格的水平正中。
```

**`attack`（出手）**：

```
这六格是【一次近身出手的分解】，从预备到还原，不循环。
六格依次是：
1 起手：重心后坐，出手那只手收回到身侧
2 蓄力：身体拧转，肩膀带动
3 出击：手臂开始伸出，重心前移
4 伸到最远的那一瞬间：手臂完全伸直，伸得比其余五格都明显更远
5 收回：手臂开始撤回，重心回正
6 还原：回到和待机接近的站姿
第 4 格是整套动作的命中瞬间，它必须是六格里手伸得最远的那一格。
每一格里角色的双脚都踩在这一格的基线上，不腾空。
```

> **第 4 格那句不能省。** [method PBActorForge._pick_reach] 挑的就是
> 「从脚底中点往右到剪影右沿最远」那一格，并把它当成 `attack_0` ——
> 素材规格第 8 节的硬要求是**打出去那一下必须是第 0 帧**。
> 起手排在前面的话，游戏里伤害结算比画面早半拍，
> 玩家看到的是「**先掉血、后挥手**」。

**`dead`（倒地）**：

```
这六格是【倒地】，从中招到完全不动，不循环。
六格依次是：
1 中招：身体一顿，上身微微后仰
2 踉跄：向后退半步，重心不稳
3 下沉：屈膝，上身前倾
4 跪地：单膝着地，一只手撑地
5 倒下：向画面右侧侧倒，身体接近水平
6 躺平：完全侧躺在地上，四肢松弛，不再有任何动作
第 6 格是终态：一个完全静止、完全躺平的姿势，身体的最高点不超过
站立时腰部的高度。六格全部面朝右，倒下的方向朝画面右侧。
```

> **第 6 格必须是终态**：游戏里倒地段播完会**停在最后一帧**
> （[method PBActorPose.holds_last]），停在一个还没躺稳的姿势上，
> 屏幕上就是一具半跪着定住的尸体。

### 2.7.5 出图之后当场检查四条

**这四条错了都不报错**，而且全都要等素材进了游戏才看得见：

1. **六格里的人一样大。** 量两格的身高，差超过 5% 就重出这一张。
   `scales()` 按段取**一个**缩放比，同一段里逐格的差异原样留下来 ——
   表现是这个角色在动画里**忽大忽小**。

   **跨图集的大小不用管**：按图集切的时候四段一律借 `idle` 的比
   （`PBActorForge.scales` 的 `share_idle`）。这条不是为了省事 ——
   逐段归一化的前提是「这一段里总得有一帧人是站直的」，而 `run` 那张
   六格全是弓着腰的跑姿，最高的一格也只有站姿的七成
   （实测卡卡西：站姿 880，`run` 那张最高 615），照自己量会把跑动的人
   **放大 43%**，而每一帧看起来都很正常。

   代价是 **`idle` 那张必须是站姿，而且必须第一个切** ——
   另外三段都要借它的比，缺了它插件会直接拦下来。
2. **格与格不粘连。** 切图靠的是洋红空隙；两个人物碰上了，包围盒会连成
   一片，切出来是「一格里有一个半人」。
3. **脚下没有影子、没有横线。** 一条横贯全图的地面阴影会同时弄坏三样：
   [method PBActorForge._feet_x] 只看包围盒最下面一成，那一成全是黑影，
   于是「脚底中点」变成**画面正中**；[method PBActorForge.fit_canvas]
   的画布宽跟着涨到**半个屏幕**；地面线落在黑影底边，人因此**悬空**。
   有残留就用形象插件里的**橡皮**擦掉（框选一次「套到整段」）。
4. **`attack` 那张的第 4 格确实伸得最远。** 不是的话挑帧会挑错，
   游戏里就是「先掉血、后挥手」。

### 2.7.6 出图之后走哪一步

图集**不能直接进管线** —— [method PBActorForge.measure] 扫的是
「一个目录里一帧一个 `.png`」。所以顺序是：

**四张图集 → 切成 4 × 6 张单帧 PNG（每段一个目录）→ 形象插件挑帧 → 导出四段 → 生成形象表**（§4.0.3）。

切分靠的是格与格之间那道洋红空隙（按行列投影找空白带）。
切完**必须肉眼看一眼**：切歪了带进半个邻居，包围盒就错，
而画布、坐标、锚点全部看起来完全正确。

---

## 3. 出图之后：三步降采样对齐（这一步不能跳）

工具用 Aseprite（最顺手）、或者 Photoshop / GIMP / libresprite 都行。

1. **抠背景。** 按洋红色选中，删掉。**边缘不要羽化** ——
   留下的半透明像素在游戏里会变成一圈脏边。
2. **降到 60 像素高**（高清档是 180，见素材规格第 2 节）**。**
   像素档的缩放算法必须选**最近邻 / Nearest Neighbor**
   （Aseprite 里是 `Sprite > Sprite Size > Nearest`）。
   双线性会把每个像素糊成四个半调像素，像素风当场消失。
   降完**一定要手工修一遍**：眼睛、发梢、武器这些一两像素的东西
   降采样之后必然糊掉，得手动点回来。
3. **对齐画布。** 新建 62 高的画布（高清档 186，宽按内容加宽），把人贴进去，
   **脚底落在最底一行、水平居中**。
   同一个角色的**所有帧共用这一个对齐**——逐帧各对各的，人会在动画里抖。

自查（和规格那页的清单是同一份）：

- [ ] 同一个角色的每一帧尺寸完全一致（make_actor.ps1 生成的是 64×48）
- [ ] 脚踩在最底一行，水平居中
- [ ] 全部朝右（或者全部朝左，并在 `.tres` 里说明）
- [ ] 有 1px 深色描边
- [ ] 没有半透明边缘
- [ ] `attack` 的**第一帧就是打出去的那一下**（起手动作 0~1 帧，收招可以长）

## 4. 装进游戏：一条命令

**第 3 节那三步（抠背景、降采样、对齐）加上建 `SpriteFrames`，全部自动了**
（M6-f）。视频那条路上不用开 Aseprite，也不用开 Godot 编辑器：

```powershell
.\scripts\make_actor.ps1 -Key asm
```

它要的输入是 `aires\<Key>_<段名>.mp4` 四段（`idle` / `run` / `attack` / `dead`），
每段一条视频，按第 2.5 节那套提示词生成、洋红背景。跑完得到：

```
assets\actors\asm\*.png            10 张成品帧
data\actors\frames\asm.tres        图集（SpriteFrames）
data\actors\asm.tres               形象表（PBActorSkin）
```

**最后只剩一步是手做的**：把 `data\characters\<角色>.tres` 的
`actor_key` 填成 `asm`（那是个纯文本文件，加一行就行）。然后开预览台看（§4.6）。

### 4.0 它替你做了什么

| 手做的那一步       | 自动版怎么做的                                           |
| ------------------ | -------------------------------------------------------- |
| 抠洋红背景         | ffmpeg`colorkey`                                       |
| 降采样不糊         | **预乘 alpha** 再按面积平均 —— 见下面那条        |
| 对齐画布           | 量出**脚底那一截的中点**，坐到画布底边中点上       |
| 挑帧               | 量出来的：跑动做剪影自相关找循环、攻击取手伸得最远那一帧 |
| 定画布尺寸         | 按挑中的那几帧算，装得下出拳的伸展                       |
| 加 1px 描边        | 把剪影最外圈压暗（**不往外扩**，扩了身高就超了）   |
| 建`SpriteFrames` | 脚本写`.tres`，帧率与循环按段设好                      |

> **「预乘」那一条是这条链上最容易错的地方。** 抠完背景之后背景像素虽然
> 全透明了，它的 RGB 仍然是洋红 —— 缩放会把相邻像素平均起来，
> 于是人物边缘渗出一圈粉色，**而 alpha 看起来完全正常**。
> 先把透明像素的 RGB 归零（`rgb *= a`）再缩，缩完除回来。

> **挑帧不靠数格子。** `attack` 的第一帧必须是打出去的那一下（规格第 8 节），
> 靠肉眼在联络表上数十次有三次差一帧，而差一帧的表现是
> 「先掉血、后挥手」。脚本量的是「从脚底中点往右到剪影右沿有多远」，
> 取最大的那一帧。跑动同理：循环长度靠剪影自相关量，数错一帧就一瘸一拐。

### 4.0.1 常用开关

| 开关                       | 干什么                                                 |
| -------------------------- | ------------------------------------------------------ |
| `-SkipExtract`           | 视频没变、只改了切图参数时跳过 ffmpeg 那一趟（快很多） |
| `-Anims idle,run,attack` | 只有三段视频时用（`dead` 缺了会退回待机段）          |
| `-SrcDir <目录>`         | 视频不在`aires\` 时                                  |
| `-Preview`               | 跑完直接开预览台                                       |

> **M6-n 起高清档是唯一的档**（玩家定的：不再出像素档），所以没有开关 ——
> `PBActorForge.scale_up` 默认就是它。像素档那一档的代码留着，
> 因为它是整条流水线的退化参照、测试还在两档之间对拍；
> 真要把它请回来，改的是那个字段的默认值。
>
> 两档的对照见[素材规格](素材规格_战场形象.md)第 2 节那张表。
> 一句话：像素档是硬边像素画，高清档不是——它边缘是软的，
> 1080p 下细节多三倍，代价是和界面那些硬边像素不是一路。

### 4.0.2 从零走一遍（以阿斯玛为例）

#### 第 0 步 · 摆好四段视频

**文件名就是这条流水线唯一的接口**，没有配置文件、没有参数表：

```
aires\asm_idle.mp4
aires\asm_run.mp4
aires\asm_attack.mp4
aires\asm_dead.mp4
```

`asm` 是你给这套形象起的**键**，规矩三条：**短、全小写、不带空格和中文**。
它会变成目录名（`assets\actors\asm\`）、形象表名（`data\actors\asm.tres`），
以及角色表里那个 `actor_key`。后面三段的名字（`idle` / `run` / `attack` / `dead`）
**是固定词，不能改** —— 脚本按它们找文件，也按它们建动画段。

视频本身的要求见 §2.5：**纯洋红背景（`#FF00FF`）、正侧面、原地不位移**。
只有三段也能跑，见上面 4.0.1 的 `-Anims`。

#### 第 1 步 · 跑那条命令

```powershell
.\scripts\make_actor.ps1 -Key asm
```

一到两分钟，中途不需要任何操作。屏幕上会依次走过五步：

```
── 抽帧（抠洋红 + 预乘 + 缩到 960×540）
  idle     97 帧
  run      97 帧
  attack   97 帧
  dead     97 帧
── 切成成品帧
── 导入新贴图
── 连线（SpriteFrames + PBActorSkin）
── 再导一次（把新写的 .tres 收进去）
完成。
```

**中间那堆 960×540 的帧落在 `build\aires\mid\`**，那是中间产物，
`.gitignore` 里，随时可以删；重跑时它会自己重建。

#### 第 2 步 · 把角色指过去（唯一手做的一步）

脚本不知道这套形象是给哪个角色的 —— 那是你的决定，所以它只能你来填。
用记事本或 VSCode 打开 `data\characters\asuma.tres`，在 `id` 那一行下面加一行：

```gdscript
id = &"asuma"
name_key = "char.asuma"
icon_key = "char.asuma"
actor_key = &"asm"        # ← 加这一行
```

**`&"` 和结尾的 `"` 一个都不能少**（那是 GDScript 的 StringName 写法）。

#### 第 3 步 · 开预览台验收

```powershell
F:\Godot_PJ\_engine\4.7.2\godot.exe --path . res://scenes/actor_lab.tscn
```

或者 VSCode 里 `F5` → 「Godot: 战场形象预览台」。左边下拉框挑到那个角色，
**右边信息栏那三行就是验收单**：

| 那一行写着                     | 意思                                                                      |
| ------------------------------ | ------------------------------------------------------------------------- |
| 来源**data/actors**      | 这张皮装上了。写「**白模兜底**」= 没装上，回第 2 步查 `actor_key` |
| **五段齐全**             | 段名都对得上。写「缺 xx」= 那一段没帧，游戏里会静默播上一段               |
| 脚底十字**压在地面线上** | 锚点对了。浮一格 / 陷一格在战斗画面里看不出来，在这儿一眼看得见           |

五段动作各放一遍（尤其 `attack`：**第一帧就该是打出去的那一下**），
放大到 4 倍、翻转朝向各看一次。

#### 第 4 步 · 自检

```powershell
.\scripts\check.ps1
```

`tests\test_actor_data.gd` 那九条会把这套素材过一遍（帧尺寸一致、
脚真的踩在画布底边上、`actor_key` 查得到）。绿了就能开游戏看了。

#### 出错对照表

| 屏幕上出现的                         | 意思                                      | 怎么办                                                              |
| ------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------- |
| `找不到 ffmpeg`                    | 没装，或装完没重开终端                    | `winget install Gyan.FFmpeg`，**装完新开一个 PowerShell**   |
| `少一段视频：...`                  | 文件名对不上                              | 按`<Key>_<段名>.mp4` 改名，或用 `-Anims` 只列你有的那几段       |
| `这一段一帧都没读到`               | ffmpeg 那趟没产出，或`build\` 被清了    | **别加 `-SkipExtract`** 再跑一遍                            |
| `这一段一帧都没有（第一趟跑了吗）` | 第一趟没成功就跑到了连线那步              | 从头跑一遍，看第一趟有没有报错                                      |
| 预览台写「白模兜底」                 | `actor_key` 没填、拼错，或填的是角色 id | 第 2 步。**拼错一个字的表现就是「还是白模」，不报错**         |
| 人物边缘发粉                         | 视频背景不是纯洋红，或 AI 加了运动模糊    | 重出视频：背景纯`#FF00FF`、镜头不动、别要运动模糊                 |
| 人浮在地面上方 / 陷进地里            | 脚底没量准（鞋底那排太薄，被阈值切掉）    | 预览台看脚底十字；调`make_actor.gd` 的 `ALPHA_CUT`（默认 0.45） |
| 攻击「先掉血、后挥手」               | 起手动作被当成了第 0 帧                   | 那一段重出：**从蓄力完成开始拍**，别让起手占前两帧            |

#### 改完参数重跑

切图参数（画布、描边、阈值）都在 `src\tools\make_actor.gd` 顶部的常量里。
改完**不用重新抽帧**：

```powershell
.\scripts\make_actor.ps1 -Key asm -SkipExtract
```

ffmpeg 那一趟是整条链里最慢的（四段视频各解一遍），跳过它快好几倍。

### 4.0.3 想自己挑帧：编辑器里那块「战场形象」面板

命令行那条路挑哪几帧是**算出来的**（剪影自相关找跑动循环、伸展量找出拳那一帧）。
那套算法八成是对的，但**错的时候不吭声** —— AI 视频里总有一两帧手比划到一半、
或者人整个糊掉，算法照样会挑中它，而你只有出完开预览台一段段看才发现。

M6-l 起有一块面板把那一环换成人：**帧就在眼前，点哪张要哪张。**

#### 怎么打开

1. 双击 `F:\Godot_PJ\_engine\4.7.2\godot.exe`，在项目列表里选 PixelBattle（或者直接
   `godot.exe --path .`）
2. 编辑器**下边**那一排按钮（输出、调试器、动画…）里点 **「战场形象」**

> 插件已经在 `project.godot` 里启用了，不用手动去 Project Settings 里勾。
> 那一排按钮找不到的话，把编辑器底部往上拖一点。

#### 面板怎么用

左边一栏从上往下就是操作顺序：

| 步 | 干什么                                                                     |
| -- | -------------------------------------------------------------------------- |
| 1  | **角色键**填 `asm` 这种短名字（会变成目录名和 `actor_key`）      |
| 2  | **这一段**选 `idle` / `run` / `attack` / `dead`              |
| 3  | **选视频…** 挑这一段的 mp4                                          |
| 4  | **抽帧并载入** —— 跑 ffmpeg，十几秒，期间编辑器会卡住（正常）      |
| 5  | `◀ ▶` 或拖滑块翻帧，看中了按 **＋ 要这一帧**（再按一次取消）     |
| 6  | 图集那条路直接按**全部选择** —— 6 格按顺序一次填满，再逐帧改      |
| 7  | 四段都抽过帧了，按**① 导出四段（帧自动定）** 一把全出               |
| 8  | 逐段翻着看。某一段不对就回第 5 步重挑，按**② 导出（只覆盖这一段）** |
| 9  | 都行了，按**③ 生成形象表**                                          |

**这就是一个新角色的全部走法。** ① 负责从零到有（从零翻 97 帧 × 4 段太贵，
而算法挑的八成对），② 负责改，③ 负责装表。

右边是预览，上面画着两条线：**蓝框**是这一帧人物的包围盒，**黄线**是脚底中点和
地面线。**黄线是最要紧的那条** —— 出拳那几帧手伸出去老远，包围盒中心会跟着偏，
而对齐用的是脚。

#### 三条要知道的

- **② 是一段一段的**（M6-n）。画布按内容算，出拳那一段几乎总是最宽 ——
  所以它会取「这一段要的」和「已经在盘上的」两者的最大值，需要变大时把
  旧帧重新裱一遍（纯补透明边，不重采样）。「同一个角色每一帧尺寸一致」
  是测试钉着的，那条不变量因此没破。
- **先按 ① 的话画布一次就定在最终尺寸上**（四段一起量），后面逐段覆盖
  基本不用再重裱。反过来先导窄的那几段，等导到 `attack` 时要把前面
  全部重裱一遍 —— 结果一样，只是多跑几趟。
- **① 一律现定，不看你已经挑过的名单**（按钮上就写着「帧自动定」；
  「有时候用我挑的、有时候不用」是一个说不清的按钮）。定好的名单会填回
  各段的列表里，接着改就是了。
- **② 没挑过就自动挑**，挑完的名单会显示在列表里，可以再改。
- **「全部选择」替掉了原来的「自动挑」**（M9-l）。那套算法是按「从几十上百帧的
  视频里挑 6 帧」写的，头尾各掐掉 8 帧 —— 而图集进来的就已经是 6 格，
  6 全在掐掉的范围里。实测它在 6 格上给 `idle` 挑出 `[5, 5]`（只有两帧，
  而且都是最后一格）、给 `dead` 挑出 `[0, 2, 4, 5, 5, 0]`（**最后一格回到了
  站姿**），**而这四段一条都不报错**：名单是满的、导出照跑、帧数也对。
- **① 和 ② 的空名单兜底跟着按源帧数分岔**（`PBActorForge.frames_for`）：
  帧数正好等于一段要的帧数就按顺序全要，多得多才走算法。所以**图集那条路
  上 ① 也是安全的** —— 走视频那条路时算法照旧。
- **导 `dead` 要先抽过 `idle` 的帧**：人躺着，包围盒高度不是身高，
  缩放比得借 `idle` 的。缺了会明说，不会静默出一个躺着也「站那么高」的人。
- **视频没变、只想重挑**：按「读已抽的帧」，跳过 ffmpeg 那十几秒。
- **状态栏说「撞上头顶上限，头被切掉了一截」就得回去改挑帧**：画布高度有个
  硬上限（见素材规格第 2 节），挑中的帧里有跳得特别高的那一张就会顶上去。
  被切掉的是**头**（脚是坐在底边上的），而画布、坐标、锚点全部看起来完全正确。

#### 它和命令行是同一条流水线

抠背景、量、定画布、缩、坐到底边、描边 —— 全在
[`PBActorForge`](../src/tools/actor_forge.gd) 一个类里，两条路都只是它的调用方。
所以**两边出的素材逐字节相同**（M6-l 抽出来那天拿阿斯玛对过一遍，`git diff` 是空的）。

批量走 30 个角色时仍然用命令行：没人想点 120 次按钮。

### 4.0.4 手做那条路（下面 4.1~4.5）什么时候还需要

第 0 节的 A / C 两条路线（文生图、PixelLab）产出的是**散帧**不是视频，
`make_actor.ps1` 现在只吃视频。那两条路仍然照 4.1~4.5 手做，
或者先把帧拼成一段视频再喂给它。

假设角色叫 `naruto`（`actor_key`，小写英文 + 下划线，**不要用中文名**）。

### 4.1 放文件

把切好的帧放进 `assets/actors/naruto/`：

assets/actors/naruto/idle_0.png  idle_1.png

assets/actors/naruto/attack_0.png  attack_1.png  attack_2.png

### 4.2 关掉纹理过滤（**漏了这一步整套图会糊**）

但如果某张图在编辑器里被单独改过导入设置，要在**导入面板**里把
`Filter` 关掉、`Mipmaps` 关掉，然后按「重新导入」。

### 4.3 建 `SpriteFrames`

1. 新建一个资源，类型选 `SpriteFrames`，存成
   **`data/actors/frames/naruto.tres`**（注意是 `frames/` 子目录 ——
   `PBActorLibrary` 把 `data/actors/` 下的每个 `.tres` 都当成一张
   `PBActorSkin`，图集放它旁边的话每次读表都刷一条错误，而游戏照跑）
2. 双击打开，底部的动画面板里建三段：`idle` / `run` / `attack`
   （**名字必须是这三个**，或者在下一步的 `.tres` 里改映射）
3. 每一段把对应的 png 按顺序拖进去
4. 每一段设帧率：`idle` 4~6、`run` 10~12、`attack` 12~16
5. 循环：`idle` 和 `run` 开，**`attack` 关**
6. 把默认那个空的 `default` 段删掉

### 4.4 建 `PBActorSkin`

新建资源，类型选 `PBActorSkin`，存成 `data/actors/naruto.tres`，填：

| 字段                                           | 填什么                                                               |
| ---------------------------------------------- | -------------------------------------------------------------------- |
| `key`                                        | `naruto`（和文件名一样；留空会按文件名兜底）                       |
| `frames`                                     | 拖`frames/naruto.tres` 进来                                        |
| `anim_idle` / `anim_run` / `anim_attack` | `idle` / `run` / `attack`                                      |
| `anim_cast` / `anim_dead`                  | 有就填，没有留着——查不到会自动退回攻击段和待机段                   |
| `skill_anims`                                | `{ 忍术 id: 段名 }`，没有就空着                                    |
| `source_faces`                               | 你画的是朝右就`RIGHT`，朝左就 `LEFT`                             |
| `pixel_scale`                                | `1.0`。**要放大只能填整数**，非整数会切碎像素栅格            |
| `foot_offset`                                | **留 `(0,0)`**，那表示「画布底边中点」，也就是规格里的默认锚 |
| `tint_by_element`                            | **`false`**（真素材自己有颜色，再染一层会把美术定的色拉偏）  |
| `height_px`                                  | 站着时从脚底到头顶多少像素，36 画布的话一般填`27`                  |

那里的小人只有 60 像素高、被别人挡着，而且一秒钟之内会自己切三次状态。

信息栏那两行就是下面这份排查表的**现成答案**：

| 它写什么                       | 意思                          |
| ------------------------------ | ----------------------------- |
| 来源`data/actors`（绿）      | 皮装上了                      |

| `五段齐全`（绿）             | 五个段名都对得上              |
| `缺段：跑动（已退回）`（红） | 第 4 条，那一段静默退回了待机 |

2. `.tres` 没放在 `data/actors/` 下面
3. `frames` 那一格是空的
4. 段名和 `SpriteFrames` 里的对不上——这一条**会退回待机段**而不是白模，
   现象是「他会站但不会跑」
